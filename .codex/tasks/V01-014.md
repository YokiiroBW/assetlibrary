## 目标

在 GatewayAuth 内交付首位本地系统管理员引导与既有管理员带外凭据恢复的内部核心，使“系统尚无管理员”和“管理员全部无法登录”不再需要数据库 owner 手写 SQL。所有操作必须先经过不可省略、与动作/operation/目标绑定且有期限的带外授权端口；新管理员口令继续经过 V01-013 风险检查和 V01-012 凭据派生，再由 PostgreSQL 原子执行一次性状态约束、授权 ID 防重放、credential/session version、会话撤销和无 secret 审计。本任务仍是 component-only：不提供真实部署授权 secret、HTTP/CLI/Host 入口，不连接生产环境，也不解除生产认证、业务、文件写入或发布门禁。

## 已批准的安全合同

- Application 定义并强制调用带外授权 verifier；输入必须绑定稳定动作、调用方生成的 UUID operation ID、目标账号和有效期限。`Rejected`、`Expired`、`Unavailable`、超时、异常或未知状态一律失败关闭，且不得调用风险检查、派生器或 store。
- verified authorization 只包含随机 authorization ID、绑定语义和到期时间，不包含原始部署/恢复 secret；authorization ID 只能成功消费一次。同 ID、同 operation 和同语义可幂等重放，同 ID 绑定不同 operation/动作/目标必须冲突。
- 首位管理员引导只能在数据库从未存在任何本地系统管理员时成功；它固定创建启用的本地系统管理员，不能借此创建普通用户、覆盖账号、改变既有主体或在管理员被停用后重新走 bootstrap。
- 带外恢复只能作用于已存在的本地系统管理员；不得创建新账号、提升普通账号、改变账号名/subject/管理员事实或恢复任意外部 OIDC 主体。成功时替换凭据、重新启用目标、清除失败退避、增加 credential 与 principal session version，并撤销全部旧会话。
- bootstrap/recovery 的每个新口令都必须满足 V01-012 的 Unicode/长度规则，经过 V01-013 `ILocalSecretRiskChecker`；只有 `Allowed` 才能派生和写入，`Common`/`Compromised`/`Unavailable`/超时/异常全部零凭据写入。
- 凭据继续使用 V01-011/V01-012 冻结的 PBKDF2-HMAC-SHA256、至少 600,000 次迭代、独立 16-byte 随机盐和 32-byte 派生值；口令、授权 secret、盐、摘要、风险正文、会话 token 和异常正文不得进入审计、幂等指纹、日志或持久恢复状态。
- PostgreSQL 使用全局事务 advisory lock 串行化 bootstrap/recovery 的安全状态检查。migration 12 新增 module-owned 幂等审计/authorization-consumption 状态与两个有界函数；runtime 不能直接读写表，只能执行获批函数。
- 数据库必须再次检查 bootstrap 的“从未有管理员”事实和 recovery 的“目标仍是本地管理员”事实；不能只相信 Application 传入的布尔值。授权到期时间也必须在事务内再次检查。
- 所有 verifier 与 PostgreSQL I/O 支持取消和绝对截止；公开结果使用稳定枚举，不向调用方泄露“账号是否存在”、数据库异常或授权验证细节。
- 真实部署授权 verifier、secret 生成/保存/轮换、操作者 CLI、HTTP endpoint 和 Host DI 不属于本任务。缺少真实 verifier 时生产流程不可构造；严禁用 allow-all、环境开关、数据库 owner SQL 或测试替身作为生产回退。

## 架构、复用与依赖

- GatewayAuth 仍是唯一 owner；Application 依赖授权/风险/派生/store 端口，Infrastructure 实现 PostgreSQL store，Domain/Application 不依赖 Npgsql、ASP.NET、文件系统、网络或具体 secret Provider。
- 复用 `LocalSecret`、`ILocalSecretRiskChecker`、`ILocalCredentialDeriver`、凭据 enrollment material、账号名/显示名、PostgreSQL executor、固定 owner/runtime 角色和 migration 机制；不复制 PBKDF2、风险查询或会话撤销规则。
- 只使用现有 .NET 10 BCL 与已锁定 Npgsql；不新增语言、框架、NuGet 包、数据库、公开 wire contract 或角色。
- operation、authorization ID、账号名和主体 ID 均走唯一键/索引；单操作 `O(log n)`，会话撤销只处理目标主体，与 50 万资产无关。

## 自动测试与负向验收

1. 授权：拒绝、过期、不可用、超时、异常、错 action/operation/target 和调用方取消；全部在风险、派生和 store 前停止，错误信息/日志不含 proof 或验证细节。
2. 风险与派生：短/超长/畸形、常见、泄露、Provider 不可用/超时全部零 store；`Allowed` 才使用冻结 PBKDF2 参数和独立盐。
3. bootstrap：空系统首次成功；重复 operation 幂等；不同 operation 或并发请求最多一个成功；账号/subject 冲突不覆盖；曾有管理员后即使其禁用也不能再次 bootstrap。
4. recovery：只允许既有 local 系统管理员；普通账号、未知账号、OIDC 主体、绑定漂移和陈旧目标全部失败关闭且不泄露存在性。
5. 消费与审计：authorization ID 跨 operation/动作/目标重放冲突；审计不含 secret/salt/digest/token/风险正文；runtime 无表权限且不能调用内部 helper。
6. 会话安全：恢复原子增加 credential/session version、清除退避、撤销旧会话并重新启用；失败、重放和冲突不重复增加版本。
7. PostgreSQL 16：完整/重复 migration、runtime 最小函数权限、真实 bootstrap/recovery、并发、重启持久化、索引和 owner 边界。
8. 运行 locked restore、format、Release build、GatewayAuth .NET suite、真实 PostgreSQL 16 database suite、repository、architecture、release audit 与 `v0.1-start`；`--require-ready`/`v0.1-release` 仍按预期阻断。
