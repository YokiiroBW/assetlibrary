## Known execution environment

- Linux x86-64, Python 3.12; cgroup v2 is mounted but the root is not writable.
- `unshare`, `prlimit`, `systemd-run` and `bwrap` exist. Direct `unshare -n`
  fails with `Operation not permitted`; a minimal bubblewrap sandbox also fails
  due namespace/UID-map permissions.
- No Windows host or PowerShell is available. A task-local .NET SDK may exist in
  system temp from M0-004, but the production Worker stack is not frozen.

These are facts to probe, not permission to weaken isolation claims. Python is
allowed only as a test supervisor and opaque worker fixture. Do not add a Python
production Provider framework or install privileged/system components.

## Required outcomes

1. Evolve `contracts/providers/**` into a versioned candidate manifest and
   bounded RPC envelope set for discover/handshake/request/result/error/cancel/
   health. Include request correlation, API version/capability negotiation,
   provider identity/version, explicit trust class, library scope, permissions,
   resource limits, deadlines and maximum message/artifact sizes. Preserve
   unknown optional fields and future capability strings.
2. Keep `original_write` permanently false at the Provider boundary. Network is
   denied by default and only an explicit approved manifest permission may ask
   the supervisor for a network-enabled profile. Provider output is metadata,
   suggestions or derived artifacts in a supervisor-owned temporary area; it
   never performs the core's physical operation plan.
3. Implement a test-only supervisor/worker fixture under the Spike directory.
   Use framed bounded messages (not unbounded reads), sanitized environment,
   controlled working directory, closed inherited descriptors, process-group
   ownership and an absolute request deadline. On timeout/cancel/protocol error,
   terminate the entire worker tree with bounded escalation and reap it.
4. Prove happy response, cancellation, hang, crash, malformed/oversized frame,
   stdout/stderr flood, child-process spawn, memory pressure, CPU pressure,
   descriptor exhaustion and restart/backoff/circuit-breaker behavior. Fault
   fixtures must be tightly bounded and run only in the isolated runtime area;
   do not create an uncontrolled fork bomb or resource exhaustion test.
5. Enforce and measure every limit available on this Linux host (for example
   rlimits and a writable delegated cgroup/systemd user unit if available).
   Probe network and filesystem namespace isolation. If hard network denial,
   read-only input exposure, writable-temp confinement or child-tree accounting
   cannot be enforced here, preserve the exact failure and keep the handoff
   partial rather than replacing enforcement with a manifest assertion.
6. Define and document the Windows candidate mapping (Job Object limits and
   kill-on-close plus an appropriate restricted-token/AppContainer boundary)
   and Linux mapping (cgroup v2/systemd delegation plus namespaces/seccomp or an
   approved sandbox launcher). Prepared scripts/config may be included, but
   only executed evidence counts as passed.
7. Validate safe mode and trust behavior: official/signed Provider candidates
   may load under approved policy; side-loaded Providers are disabled in safe
   mode, limited to explicit test libraries and cannot broaden their own
   manifest permissions. Signature verification implementation is not required
   unless it is fully test-local and uses no new production dependency.
8. Prove Provider failure degrades the asset to L0 instead of hiding it or
   blocking the library. AI/online Provider absence must leave base browsing,
   file identity and external-open metadata usable.
9. Record cross-platform mechanism gaps, runtime overhead, restart latency,
   dependency/license implications and the exact decisions M0-009 may freeze.

## Interfaces and compatibility

- Provider adapters depend only on the versioned Provider contract. Domain and
  Application never depend on concrete Provider processes or platform sandbox APIs.
- IDs, capability names, errors and states are explicit strings; unknown
  optional data is retained. Unsupported Provider API versions fail closed.
- Message size, artifact size, deadline, memory, CPU, process and descriptor
  limits are explicit and checked before dispatch. Logs are structured and
  contain no credentials, real paths or private metadata.
- A Provider request references a supervisor-issued opaque input/artifact token,
  not an unrestricted arbitrary host path. Result acceptance never implies a
  physical write or trusted metadata promotion.
- Candidate contracts are not frozen production APIs until M0-009 accepts them.
