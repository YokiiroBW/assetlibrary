## Required outcomes

1. 写出一份规范性协议候选，明确传输映射、媒体类型、版本策略、兼容规则、限制值与错误语义。控制和事件必须可由 Chromium 原生 API 使用；大文件必须流式传输，不得把 100GB 内容整体放入 JSON 或内存。
2. 完成握手与能力协商契约：客户端提供支持版本/能力，服务端选择兼容版本并返回稳定 server_id；主备端点切换必须验证同一服务身份，不支持的主版本必须明确失败。
3. 完成控制请求/响应与统一错误信封：请求关联、取消、超时、幂等键和可重试提示必须有明确语义；未知可选字段保持前向兼容。
4. 完成事件信封与恢复契约：不透明游标、顺序、断线重连、补齐、游标过期和重建策略必须可通过固定夹具验证。
5. 完成下载 Range 与分块上传契约：transfer ID、64 位长度/偏移、分块强哈希、最终强哈希、重复分块、状态查询、恢复、完成与取消均需定义；成功不得仅依赖返回码。
6. 提供有效、无效、旧次版本、新次版本、未知字段、未知能力、断线与重试夹具，以及标准库可运行的契约测试。测试必须证明关键回归在原始草案上会失败。
7. 提供官方 SDK 消费映射说明或最小生成边界，至少覆盖 .NET、TypeScript 和 Kotlin 的 64 位数字、未知字段与枚举演进；不要手写三套业务逻辑。
