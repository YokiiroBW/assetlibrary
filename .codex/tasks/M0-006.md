## Required outcomes

1. Define a small, explicit, versioned operation journal/state machine for
   preflight, staging/copy, verification, commit, source-to-trash and completion,
   plus cancelled, conflict and manual-attention outcomes. Journal writes must
   be atomic and durable enough for the Spike (temp file, flush/fsync, atomic
   replace, directory fsync where supported). Recovery must first inspect the
   physical source, staging file, target and trash state; it must never blindly
   replay the last database/journal intent.
2. Implement preflight checks for library-root containment, normalized relative
   paths, lexical and resolved traversal, symlink escape, source regular-file
   identity/stability, protection/permission decisions, target collision,
   required free space and same-device/cross-device classification. Separate
   deterministic policy/fault inputs from OS observations; do not rely on this
   test process running as a particular UID to simulate every denial.
3. Stream bytes with a bounded buffer while computing SHA-256. Capture source
   size/mtime (and available stable file identity) before and after copy; a
   mid-copy mutation must fail closed. A target is not verified until it can be
   reopened, fully read and independently strong-hashed. Return codes or a
   successful write alone are never sufficient.
4. For same-volume commit, execute and prove an atomic non-overwrite primitive
   such as Linux `renameat2(RENAME_NOREPLACE)`. For cross-volume move, stage on
   the target volume, fsync, verify, atomically commit without overwrite, reopen
   and re-hash, and only then move the source into the task-local trash. If the
   platform cannot provide a real no-overwrite primitive, report a blocker;
   never substitute check-then-rename under a race.
5. Inject a real subprocess crash (`os._exit` or equivalent) at every durable
   state boundary. A new supervisor process must recover from the journal plus
   physical facts. Repeated recovery must be idempotent. Before target commit,
   every failure preserves the source; after target commit, a duplicate is
   auto-resolved only when full hashes agree, otherwise it becomes an explicit
   conflict/manual-attention outcome.
6. Model operation ownership with operation/task ID, node/worker owner,
   heartbeat and expiry. An unexpired foreign owner blocks mutation. Expired
   ownership may be reclaimed only after physical reconciliation; demonstrate
   restart, stale owner, concurrent claim and cancellation behavior. Reuse the
   M0-005 lease conclusions as read-only context, but do not add or change a
   database migration for this test-only Spike.
7. Implement a unified task-local trash record containing a stable operation
   identity, reason, library ID, original relative path, trash relative path,
   size and SHA-256. Cover ordinary delete, move-source cleanup and explicit
   replacement reasons. Restore must never silently overwrite an existing path;
   same-name/same-hash may be reported as already restored, while different
   content is a conflict. Explicit replacement must put the old target in trash
   before the replacement is reported complete.
8. Prove deterministic negative paths: insufficient space, permission denied,
   protected source/target, same-name different content, symlink/traversal
   escape, source mutation during copy, target hash mismatch, cancellation,
   stale lock, service restart and repeated recovery. Fault injection must be
   bounded and must not modify global mount, quota or permission state.
9. Exercise representative real file sizes and a logical 64-bit/100 GiB boundary
   without materializing 20/100 GiB fixtures. Record the largest actual byte
   fixture, streaming buffer size, elapsed time and peak memory evidence. Reuse
   `BYTES_100_GIB`, sandbox validation or fault vocabulary from M0-007 where it
   fits; do not copy those helpers into a second generic utility layer. Do not
   claim the 1 GiB/20 GiB/100 GiB release gates were run when they were not.
10. Record an executed platform matrix: Linux same-volume non-overwrite,
    Linux cross-device recovery and every actual fsync/atomic primitive used;
    Windows candidate mapping and any filesystem-specific guarantee must remain
    an explicit external gate without executed evidence. Include the exact
    decisions and CI probes M0-009 should freeze.

## Interfaces and compatibility

- Keep the state machine test-local and explicit: enums/dataclasses or equally
  small standard-library types, a narrow filesystem operation surface and
  injected clock/fault decisions. Do not introduce speculative interfaces,
  factories, plugin systems or a generic workflow engine.
- Operation/library IDs, owners, states, errors, reasons, relative paths,
  64-bit sizes and SHA-256 values must be explicit. Persist a schema version and
  reject unknown mandatory state rather than guessing.
- Physical files are authoritative. The journal coordinates and explains an
  operation but cannot prove a file exists, is complete or is the same content.
- Filesystem-specific adapters may report unsupported guarantees. Platform
  fallback must fail closed for destructive commit, not silently degrade to an
  overwriting primitive.
- No test-only journal, state name or adapter becomes a frozen production or
  shared contract until M0-009 reviews the evidence.
