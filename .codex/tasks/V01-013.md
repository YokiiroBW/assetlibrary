## 已批准的适配器合同

- 请求目标固定为 `https://api.pwnedpasswords.com/range/{PREFIX}`；`PREFIX` 必须是 UTF-8 完整口令 SHA-1 的前 5 个大写十六进制字符。不得配置任意 origin，不跟随重定向。
- 网络上只允许出现 5 字符 prefix。明文、UTF-8 字节、完整摘要及 35 字符 suffix 不得写入 URI、header、日志、异常正文、磁盘、指标标签或缓存 key/value 中的单口令结果。
- 每次请求发送 `Add-Padding: true` 与准确、固定、低敏的 User-Agent；不需要也不得引入 HIBP API key。
- 响应仅在 HTTP 200、大小与行数均在固定上限内、每个非空行均严格符合 `35 uppercase-hex suffix : non-negative decimal count` 时有效。命中相同 suffix 且 count 大于 0 返回 `Compromised`；count 为 0 的 padding 行忽略；未命中返回 `Allowed`。
- 非 200、重定向、超时、传输异常、响应过大、非法编码/格式、重复冲突或提前 EOF 一律返回 `Unavailable`，让 V01-012 保持零凭据写入。调用方主动取消必须继续抛出取消，不得伪装成服务不可用。
- 单次远程请求绝对超时不超过 2 秒，并服从 V01-012 的外层 5 秒截止时间。响应必须流式、有界读取，禁止无界 `ReadAsStringAsync`。
- 缓存只保存按 prefix 返回的公共 suffix range，不保存某一口令的命中结果。缓存必须仅在内存中、有容量上限、有最长有效期、按到期和最久未用条目淘汰；过期条目不能在远端失败时作为允许依据，失败响应不得缓存。
- SHA-1 仅用于 HIBP k-anonymity 查询兼容，不用于凭据派生或持久化。UTF-8 临时字节、完整摘要和临时 suffix 比较材料必须尽快清零或释放；现有 PBKDF2 凭据政策保持不变。
- 必测路径使用受控 `HttpMessageHandler`/流测试替身，不调用真实互联网。不得把 live HIBP 可达性当成 required CI 证据。

## 架构、复用与依赖

- `GatewayAuth` 仍是唯一 owner。适配器位于 Infrastructure 并实现 Application 端口；Domain/Application 不引用网络或具体 Provider。
- 复用 V01-012 的 `ILocalSecretRiskChecker`、`LocalSecretRisk`、`LocalSecret` 和失败关闭 lifecycle 编排；不复制账号写入、权限、哈希派生或审计逻辑。
- 只使用 .NET 10 BCL 的 HTTP、加密、流和并发能力；不新增语言、框架、NuGet 包、数据库、共享契约或公开 API。
- 单次远端检查复杂度为 `O(response bytes)`，内存为固定响应上限加有界 cache；与账号数和 50 万资产规模无关。

## 自动测试与负向验收

1. 查询隐私：已知 UTF-8/Unicode 向量产生正确 prefix；传输只见 5 字符 prefix、padding 和固定 User-Agent，绝不见明文、完整摘要或 suffix；重定向不跟随。
2. 结果：正数命中为 `Compromised`，零计数 padding 忽略，合法未命中为 `Allowed`；大小写和 CRLF 合同按官方格式严格处理。
3. 失败关闭：所有非 200、超时、连接/读取异常、截断、超限、非法 UTF-8、非法十六进制、非法/溢出 count、重复冲突均为 `Unavailable`。
4. 取消：调用方取消及时传播；超时稳定映射为 `Unavailable`；没有后台请求或响应流残留。
5. 缓存：有效 prefix range 命中不重复联网；到期后重新请求；失败不缓存；容量淘汰确定且并发安全；过期允许结果不得在断网时继续放行。
6. 生命周期集成：`Compromised`/`Unavailable` 均让 V01-012 store 零调用，`Allowed` 才可继续派生和写入。
7. 日志与表面：异常和日志不含 secret/hash/prefix/response；Host 路由、数据库、migration 和 release gate 保持不变。
8. 运行 locked restore、format、Release build、GatewayAuth .NET suite、repository、architecture、release audit 与 `v0.1-start`；`--require-ready`/`v0.1-release` 仍按预期阻断。
