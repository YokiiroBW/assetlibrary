- dotnet is not preinstalled.

These are execution facts, not permission to weaken the gates. You may install an official SDK only into this task's ignored .runtime/sandbox-storage/ area or a system temporary directory; do not modify system packages or global configuration.

## Required outcomes

1. Confirm the current supported .NET LTS candidate from primary official documentation and record exact SDK/runtime versions, support status, license and source links in the Spike record. Do not silently use an arbitrary preinstalled version.
2. Create one minimal Spike host under the test area with a live/readiness endpoint and graceful cancellation. The same project and code must be published for linux-x64 and win-x64; platform differences belong only in host/packaging adapters.
3. Provide deterministic publish commands and manifests for Linux native execution, Windows x64 execution/service registration and Docker. Generated binaries/images remain outside Git.
4. Demonstrate Linux start, health response, graceful stop and restart. Prepare a reversible current-machine Windows service cycle and a non-root container run with health check and persistent configuration/data mount boundaries.
5. Prove or explicitly gate artifact identity: the three packages must derive from the same source commit and expose the same Spike behavior/configuration schema. Record sizes and hashes without committing build outputs.
6. Test missing configuration, occupied port, read-only data path and interrupted shutdown. No test may touch real asset directories; all writable data must stay in the isolated sandbox or temporary directory.
7. Document what is proven locally and what still requires a Windows host or Docker daemon. Without actual Windows and container execution evidence, handoff status must be partial, not accepted.
