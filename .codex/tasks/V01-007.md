## 必须实现的合同

### TransferSync

- 明确的会话 ID、幂等键、源/目标不透明 token、期望长度与 SHA-256、状态、已传输字节、最终强校验结果和稳定失败种类。
- 状态转换必须显式、不可倒退；相同幂等键与相同语义返回原会话，不同语义冲突。
- 流式执行必须有批次/缓冲上限，传播调用方取消和绝对截止时间；不得整体读入内存。
- 执行结果只有在目标重新打开、完整强哈希和长度均与预期一致后才可 `completed`。
- target exists、source changed、hash mismatch、insufficient space、cancelled、deadline exceeded 和 stale execution right 必须是可区分的失败关闭结果。

### OperationTrash

- 支持本任务范围内的 `copy`、`move`、`rename`、`trash`、`restore` 计划；`metadata-writeback`、`export`、覆盖和永久删除明确拒绝。
- 创建计划与预检不得改变物理状态；单计划项目数有界，输入路径以不透明 token 表示，绝对路径不得进入 Domain/Contracts 或日志。
- 预检至少绑定操作、项目、源物理事实、目标意图、权限/保护、容量和冲突结论，并生成不可跨计划/跨事实复用的确认摘要。
- 所有范围内操作必须在显式确认后执行；确认摘要错误、过期或物理事实变化必须重新预检，不能继续。
- `move` 只有在目标强校验完成后才允许源进入垃圾桶；`trash` 永不永久删除；`restore` 与所有目标提交都不得覆盖。
- 执行权/锁带 owner、fencing token 和到期时间；过期执行者不能提交结果。恢复必须先观察 source/stage/target/trash 的物理事实，再收敛或报告人工冲突，禁止按旧日志盲目重放。
- 批次允许部分成功，但每项结果必须独立、稳定且可重试；失败项不得污染成功项或隐藏源丢失。

## 沙箱测试适配器护栏

- 唯一允许根为当前 worktree 的 `.runtime/sandbox-storage/V01-007` 的真实后代；根本身、仓库其他路径、用户/系统目录、相对路径、UNC、设备路径和其他卷均拒绝。
- fixture 根由测试创建并写入任务专属 marker；打开时验证 canonical root、marker、非 reparse point，逐段拒绝 symlink/junction/reparse escape。
- 所有测试 token 都相对 fixture 根解析；解析后再次验证 canonical boundary。内部 stage、journal、lock、trash 路径同样受边界检查。
- 真实字节使用小型确定性 fixture；流式 SHA-256 和缓冲上限可观测。不得使用 sparse file 冒充大文件门禁。
- target 提交采用 no-replace；任何碰撞保留 source/stage/target 证据。测试结束前验证 fixture 清理和任务相关进程为零。
- 故障注入至少覆盖 stage 写后、target 提交后、源入垃圾桶前/后；新 adapter/service 实例必须根据物理事实和持久 journal 幂等恢复。
- 日志只记录 operation/session ID、状态、计数、耗时和稳定错误，不记录绝对路径、文件名、内容、哈希全文、用户信息或凭据。

## 自动测试与验收

- Domain/Application 单元测试：值对象、状态机、幂等、计划上限、确认绑定、权限/保护、执行权 fencing、取消/超时和不可信端口结果防御。
- 沙箱集成：copy/move/rename/trash/restore 正常闭环；重开完整 SHA-256；无覆盖；源变化、目标并发出现、哈希错误、空间不足、路径逃逸与 reparse 拒绝。
- 恢复矩阵：关键故障点后以新实例恢复两次；结果幂等，源优先保留，无法唯一判断时进入人工冲突。
- 并发：同一目标的两个执行者最多一个成功，loser 不覆盖且源保留；过期 fencing token 不能完成。
- 流式：至少一个多块 fixture，断言单块/缓冲上限和取消后无正式目标。
- 负向门禁：生产 composition 无此适配器；仓库扫描拒绝新增生产磁盘 API、生产启用开关、M0 gate 状态变更和沙箱外固定路径。
- 运行 locked restore、format、Release build、完整 solution test、依赖/源码/重复/复杂度/敏感日志、repository、architecture、AssetLink、数据库静态/既有 integration 和 `v0.1-start` 门禁。
- `production-file-writes` 与 `v0.1-release` 必须继续返回阻断；这是预期结果，不得改写为通过。
