## 冻结的运行时边界

- 新入口只接受环境变量 `ASSETLIBRARY_DATABASE_READINESS_CONNECTION`；禁止命令行连接串，避免进入进程列表、SCM `ImagePath`、systemd unit、shell history 或构建清单。
- 连接串作为 opaque secret 保存，任何 `ToString`、错误、日志、HTTP payload、测试报告和 build-info 均不得输出原文、用户名、数据库名、主机、密码或证书路径。
- 运行时强制有界连接/命令 timeout、小连接池、禁用详细错误；拒绝空 Host/Database/Username、任意 server `Options` 和无法解析的连接串。
- 连接登录必须可 `SET LOCAL ROLE assetlibrary_database_auditor`；运行时只在 `REPEATABLE READ READ ONLY` 事务内读取 `migration.bootstrap_state` 与 `migration.ledger`，不得读取或写入业务 schema。
- 就绪判定必须与嵌入发行物的当前 `database/migrations/production/manifest.json` 精确一致：PostgreSQL major、bootstrap format/hash、ledger 数量/顺序以及每个 migration 的 version/name/module/owner/checksum 均匹配；缺失、pending、额外版本、漂移、权限拒绝、超时或断连均不 ready。
- runtime 绝不运行 `migration_tool.py apply`、DDL、角色预配、备份或恢复。迁移仍由显式运维入口在启动前完成。
- 为保持 V01-008 已验证的 host-only 包装证据，未设置该变量时继续返回原有 `host_only` readiness；只有显式配置数据库模式时才执行本合同。后续只读业务 host 任务必须把数据库模式设为必需后，才可申请关闭 `production-database-composition` 缺口。
- 即使数据库 ready，`business_api_ready=false`、`production_file_writes_enabled=false`，认证、TLS、业务 API 与所有 release target 继续阻断。

## 架构、复用与兼容

- 数据所有者仍是 `database-migration-owner`；Host 只做 composition/readiness，不获得任何业务数据所有权。
- 复用 V01-003 manifest、bootstrap hash、ledger 和 `assetlibrary_database_auditor`；不另建平行 schema-version 表或第二迁移算法。
- 复用现有 `Npgsql 10.0.3`、CoreServer host 配置/退出码/JSON/健康入口；不新增语言、框架、数据库、第三方包或服务。
- `/healthz` 仍只代表进程活性；数据库模式下 `/readyz` 才代表 host+数据库当前可用，且绝不谎报认证、业务 API 或写入。
- 未启用数据库模式时保持 V01-008 host-only HTTP payload 和 process smoke 兼容；新增字段只出现在数据库模式。
- 检查固定九条迁移，复杂度 `O(migrations)`、内存有界，与 50 万资产数量无关；不扫描任何资产表或文件。

## 自动测试与负向验收

1. 配置：未设置保持 host-only；合法连接秘密被规范化且所有字符串化路径均脱敏；缺 Host/Database/Username、server options、无效 timeout/连接串失败关闭。
2. manifest：嵌入资源可解析且与当前九条迁移一致；空/重复/乱序/额外/字段或 checksum 漂移由纯验证器拒绝。
3. PostgreSQL：真实 16.15 完整迁移库 + auditor 成员返回 ready；非 auditor、未迁移、pending/删除/篡改 ledger、错误 major、停止数据库和超时返回稳定 not-ready，不输出连接事实。
4. 启动：显式数据库模式在 preflight 不 ready 时监听前退出，返回稳定不可用退出码；通过后 `/healthz` 正常、`/readyz` 为 `host_database` 且业务 API/生产写仍 false；运行中断库后 `/readyz` 为 503。
5. 兼容：没有数据库变量时原有 V01-008 host/process/release 静态测试仍通过，build-info 与健康探针不要求秘密。
6. 运行 locked restore、format、Release build、完整 .NET solution、真实 PostgreSQL 16.15 数据库套件、repository、architecture、release audit 与 `v0.1-start`；`--require-ready`/`v0.1-release` 仍按预期阻断。
