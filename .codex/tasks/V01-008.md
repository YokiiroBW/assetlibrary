## 必须实现的宿主合同

- 同一 `AssetLibrary.CoreServer.Host` 二进制引用唯一 `AssetLibrary.CoreServer` 核心库，并支持控制台、Windows Service 与 systemd/container 生命周期；没有按平台复制业务入口。
- 启动前验证配置：绝对 data/state 路径、允许的监听地址/端口、明确环境、固定上限；缺失或无效配置以稳定错误和非零退出失败关闭。
- 默认只监听 loopback；容器外部监听必须由容器发行配置显式给出。不得默认启用 HTTPS 伪证书、匿名业务 API 或生产写入口。
- `/healthz` 只证明进程活性；`/readyz` 只证明本任务范围的宿主配置/数据边界可用，不谎报数据库、迁移或业务 API ready。
- `--health-probe` 有小于 3 秒的绝对超时并返回稳定退出码；`--build-info` 输出版本、RID、源码提交和发行合同，不含绝对路径、主机、用户或凭据。
- 生命周期日志结构化、低敏，只含稳定事件/版本/端口/耗时；不记录 data path、连接串、环境变量、请求 body、用户或异常全文。
- SIGTERM、Ctrl+C/Ctrl+Break、SCM stop 在有界时间内退出；端口冲突、只读/不可用 data 边界和重复启动失败明确，不留下子进程或监听。

## 发行与证据合同

### 通用 artifact

- Windows x64 与 Linux x86-64 从同一源码提交、同一项目和锁文件发布；`SourceRevisionId`、deterministic/CI build 与 RID 隔离的中间目录显式固定。
- 每个 artifact 生成相对路径、长度、SHA-256 清单、发行元数据和 aggregate digest；禁止把构建机绝对路径写入产物/清单。
- 两次独立 cold publish 的完整清单一致；元数据 commit 前进不得改变固定 issuance commit 的产物。
- 所有产物只生成在 `.runtime/sandbox-storage/V01-008/**`；不会提交二进制、缓存、密钥或日志原文。

### Windows Service

- SCM 测试服务使用任务唯一名称、`LocalService`、任务沙箱 data 目录和 owner marker；ImagePath/marker 任一不匹配即拒绝修改。
- install/start/health/stop/uninstall 必须是明确动作；install 失败回滚，uninstall 只删除 owner-verified 服务与带 marker 的任务 data 真后代。
- 执行前必须同时确认目标计算机名、空任务目录、管理员会话和明确开关；默认/preflight/verify-absent 永不写系统状态。
- 最终证据包含服务身份、ImagePath、健康、停止时限及 service/HKLM/data/process/listener 全部零残留。

### Docker / Compose

- 精确 .NET SDK/runtime 补丁；最终镜像以非 root 用户运行、root filesystem read-only、`no-new-privileges`、有界 tmpfs，只有声明的 data volume 可写。
- healthcheck 使用宿主内建 probe；Compose up/health/restart/down `--volumes` 后验证容器、网络、volume 与任务目录残留。
- 测试必须使用真实可用 daemon；只有解析 Dockerfile/Compose 或缺 daemon 的 skip 不能关闭 M0-004-G2、`docker-release` 或 `v0.1-release`。

### Linux native / systemd

- Linux x86-64 artifact 与 systemd unit 使用专用非 root 身份、明确 StateDirectory、只读程序目录、最小 capability、`NoNewPrivileges` 与合理 hardening。
- install/start/health/stop/uninstall 需要批准的隔离 Linux runner 和显式 root/target confirmation；最终验证 unit、用户/目录、进程、监听和日志临时证据无残留。
- 缺少批准 runner 或仅做静态 unit 检查必须保持 `linux-server-release` 阻断，且不能借包装任务解决 M0-006-G3。

## 测试与安全护栏

- 当前主机仅允许运行无管理员、无 Docker 系统改动的 publish、进程、静态和 sandbox 测试；不启动/停止 Codex，不切换当前 Codex 用户，不修改 UAC 或系统功能。
- 所有测试根必须是当前 worktree `.runtime/sandbox-storage/V01-008` 的带 marker 真后代；脚本解析 canonical path，拒绝根本身、UNC/设备/其他卷、reparse point 和越界路径。
- 系统级脚本默认只读，写动作必须由操作者在目标 VM/lab 中显式调用；每步有 timeout，任何失败优先停止并执行 owner-guarded cleanup。
- 证据文件使用脱敏 JSON：环境/runner 事实、命令合同、exit code、时限、相对 artifact、hash、残留计数；不记录凭据、连接串、绝对用户路径或机器秘密。
- 门禁必须区分 `passed`、`blocked_missing_environment`、`failed`；禁止把 skip、文件存在或脚本文本包含某关键字记作平台通过。

- Linux：systemd hardening/static policy + 真实批准 runner 周期；缺 runner 时只报告 blocker。
