## 目标

在 `GatewayAuth` 内交付由已认证系统管理员调用的本地账号生命周期核心：预配账号、读取单个账号状态、轮换或恢复凭据、停用或重新启用账号，并在每次安全状态变更时原子失效既有会话、留下不含 secret 的幂等审计记录。所有新口令必须先通过不可省略、失败关闭的常见/泄露口令风险检查端口，再生成独立随机盐和受限 PBKDF2 派生值。本任务仍不映射 HTTP/CLI 入口，不实现首位管理员 bootstrap 或部署 secret，不在当前 HTTP-only Host 开放登录，也不改变业务、文件写入或发布门禁。

## 已批准的生命周期合同

- 调用者必须是由 V01-011 会话边界产生的 `AuthenticatedIdentity`，且 `is_system_administrator=true`；PostgreSQL 函数必须按主体 ID 与会话版本再次验证调用者仍为启用的系统管理员，不能只相信入口传入的布尔值。
- 首位管理员 bootstrap、无人可登录时的带外恢复和部署授权 secret 不属于本任务；没有已认证管理员时所有生命周期命令失败关闭。后续入口不得用数据库 owner 或直接写表绕过本合同。
- 预配账号沿用 3–64 字符规范化登录名、`local:<account_name>` subject、1–200 字符显示名和显式管理员事实；账号冲突不得静默覆盖。
- 新口令必须为 15–128 个有效 Unicode scalar，不施加字符组合规则、不阻止粘贴；每次预配、轮换或恢复都必须先调用风险检查端口。风险源返回常见、泄露、不可用、超时或异常时均不得写入凭据。
- 通过风险检查后使用 V01-011 已冻结的 `PBKDF2-HMAC-SHA256`、至少 600,000 次迭代、每次独立 16-byte CSPRNG 盐与 32-byte 派生值；明文、可逆口令、风险查询正文和原始 secret 不得持久化或写日志。
- 凭据轮换/恢复原子增加 credential version 与 principal session version、清除失败退避并撤销该主体所有现有会话；恢复可重新启用目标账号。停用同样增加 session version 并撤销会话，重新启用不得恢复旧会话。
- 禁止停用最后一个启用的系统管理员；涉及管理员可用性的变更必须在数据库内串行化并在并发下保持至少一个启用管理员。
- 每个写命令使用调用方生成的 UUID operation ID 与不包含口令材料的请求指纹。相同 operation ID 与相同非 secret 语义可安全重放并返回既有结果；同 ID 不同语义必须冲突，不能执行第二次写入。
- 审计只保存 operation ID、动作、已验证 actor principal、target principal/account、结果、版本和时间；不得保存口令、盐、派生值、会话 token、CSRF token、连接串或风险源响应正文。
- 所有 PostgreSQL I/O 支持取消和 5 秒绝对截止时间；生命周期公开结果使用稳定枚举，不泄露数据库异常详情。

## 数据库与所有权

- 协调线程批准 V01-012 在没有其他 migration writer 的独占窗口内追加连续 migration 11 并更新 manifest；禁止修改既有 `0001`–`0010`、`roles.sql`、`bootstrap.sql` 或固定角色图。
- 新审计/幂等状态和函数只位于 `gateway_auth`，由 `assetlibrary_gateway_auth_owner` 拥有；`assetlibrary_gateway_auth_runtime` 不能直接读写表，只能执行 migration 11 明确列出的 `SECURITY DEFINER` 函数。
- lifecycle 函数固定 `search_path`、校验长度/范围/摘要、重新验证 actor、参数化输入并原子更新主体/凭据/会话/审计；不得跨模块写表或 `SET ROLE` owner。
- 风险检查发生在 Application 层且是 store 写入的必经路径；本任务不提供生产 HTTP/CLI adapter，因此生产账号预配 capability 仍保持阻断。

## 架构、复用与兼容

- `GatewayAuth` 继续是身份、凭据、会话和账号生命周期的唯一 owner；授权资源归属仍由 LibraryStorage 管理。
- 复用 V01-011 的 `AuthenticatedIdentity`、`LocalAccountName`、`LocalSecret`、PBKDF2 参数、session version、Npgsql 10.0.3、PostgreSQL migration/role 机制和 5 秒执行边界；不新增语言、包、框架、数据库、host 或角色。
- 风险检查定义为 Application port；Domain/Application 不依赖文件系统、网络、Npgsql、ASP.NET 或具体 Provider。当前没有风险源实现时无法构造可用的生产预配流程，必须失败关闭。
- migration 11 推进 embedded manifest；V01-010 readiness 自然要求精确版本 11，旧、缺失、额外或漂移 ledger 继续 not-ready。
- 生命周期按唯一账号名、主体 ID 和 operation ID 索引，单次操作 `O(log n)`；会话撤销只处理目标主体，与 50 万资产无关。

## 自动测试与负向验收

1. 风险与派生：短/超长/畸形口令拒绝；常见、泄露、不可用、超时和异常全部零写入；允许口令使用随机盐、固定成本并清零临时材料。
2. 授权：非管理员、禁用管理员、陈旧 session version、伪造 actor 和无管理员 bootstrap 均拒绝；数据库重新验证 actor，不依赖入口布尔值。
3. 生命周期：预配、精确读取、轮换、恢复、停用、重新启用；账号冲突不覆盖；每个凭据变更/停用使旧 session 立即失效并清除退避。
4. 幂等与审计：相同 operation 重放不重复增版本；不同语义冲突；审计不含任何 secret；数据库异常和日志不泄露敏感材料。
5. 管理员安全：最后一个启用管理员不能停用；并发停用两个管理员最多成功一个；恢复后旧 session 仍无效。
6. PostgreSQL 16：完整/重复 migration、runtime 仅函数权限、真实创建/恢复/撤销/重启/并发、索引与 owner/runtime 边界。
7. 运行 locked restore、format、Release build、GatewayAuth .NET suite、真实 PostgreSQL 16.15 database suite、repository、architecture、release audit 与 `v0.1-start`；`--require-ready`/`v0.1-release` 仍按预期阻断。
