## 目标

Windows 进程外 Host 与 Android 的 HTTP 适配器可连接同一个真实 Core/Kestrel HTTPS/临时 PostgreSQL，使用合成资源和临时账号验证登录、目录分页、范围搜索、详情及权限失败。支架自身的通过不等于原生 UI 或设备验收通过。

## 必读与复用

已阅读 AGENTS、START_HERE、docs01/02/05/16/17/22、CODE_QUALITY、ADR-0017、read-only-trial-v1 与 web-interaction-v1。复用已有 `run_e2e.py` 的 PostgreSQL fixture/完整迁移/六个 NOINHERIT LOGIN，`TrialHostIntegrationFixture` 的生产 TrialHostFactory/隔离 Worker，真实本地 operator/认证/会话/授权查询。只在已有测试程序集内替换 HIBP HTTP 响应，不为生产提供认证绕过。

## 完成标准

- 仅在显式 `--execute` 下创建自身临时集群，自动分配 loopback 端口，最多运行 7200 秒并支持私密 stop 文件。
- 账号、口令与合成样例仅在隔离临时目录；会合文件放入继承关闭的 Windows ACL / Unix 0700 私密目录。普通证据不包含凭据。
- 对外发布精确 localhost Origin 与叶证书 SHA256；Android 使用 adb reverse 维持相同 Host/Origin/SAN，绝不放宽客户端 TLS。
- 真实首次扫描至少 138 个合成文件，支持跨越 100 条分页边界、中文路径、嵌套目录、空文件；提供不可见普通账号验证权限边界。
- 正常 stop 与生命期截止均释放 Core、数据库、六个角色、临时目录和监听器；SHA256/mtime 始终不变。故障/未运行不记为通过。
- 通过 Python runner 边界测试、C# TLS 默认兼容性与相关平台测试、真实 fixture 运行、仓库架构/协议校验，完成一次最终 diff 审查与标准交接。
