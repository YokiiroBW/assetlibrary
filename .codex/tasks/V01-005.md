## 架构与复用

- `TaskHealth` 唯一拥有 durable task、租约、取消意图、健康状态和 outbox 发布状态。
- 业务模块只能消费 `TaskHealth.Contracts` / Application 端口；不得直接更新 `task_health` 表或发布租约。
- Domain 只定义状态与转移；Application 负责输入、超时、幂等和编排；Infrastructure 留给 PostgreSQL/发布适配器实现核心端口。
- 复用 M0-005 已验证的 `FOR UPDATE SKIP LOCKED`、过期回收、outbox at-least-once 和稳定 event ID 结论，但不复制其 `tasks`/`events` Spike schema。
- 复用 V01-003 的 module owner、连续 manifest、forward-only/备份恢复与 task-local PostgreSQL 16.15；复用 V01-004 的值对象、端口、MSTest 和真实数据库测试模式。
- 不新增数据访问库；本切片冻结核心合同和数据库函数，生产 PostgreSQL adapter/组合留给后续集成任务。

## 行为与安全合同

- 入队以非空、有限长度 idempotency key 唯一；相同语义重放返回原任务，不同语义重用同 key 必须冲突。
- claim 必须原子、跳过锁、按优先级/可用时间排序且批量有上限；每次租约生成不可复用 token 和递增 generation。
- heartbeat、完成、重试和取消确认必须同时匹配 task ID、owner、token、generation 与未过期租约；旧 worker 不得提交新租约结果。
- 排队任务取消立即终止；租约中任务只记录取消意图并保留围栏，worker 在心跳/检查点观察并确认；过期回收将已请求取消的任务置为 cancelled。
- retry 只对显式可重试失败且未超 max attempts 的任务重新排队；其余进入 failed。错误码有限长，不记录凭证或任意异常正文。
- outbox 只承诺 at-least-once；event ID 是消费者幂等键。claim/发布/释放均受 owner+token+generation 围栏，失败按 `available_at` 延后，达到上限进入 dead-lettered，记录不静默删除。
- outbox payload 只作为不透明 JSON 保存，不写日志；同 event ID 的不同内容必须冲突。
- 健康状态只允许正常、降级、警告、离线、维护中、初始化中；scope 仅系统、资源库、资产，系统 scope 不得带资源 ID，其余必须带非空 ID。
- 所有超时、批量、租约、重试、字符串和 payload 大小均有硬上限；默认测试不得访问网络、真实数据库或真实资产。
