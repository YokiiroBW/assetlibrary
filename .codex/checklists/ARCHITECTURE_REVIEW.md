# 架构一致性评审清单

## 边界

- [ ] 修改属于明确模块，目录和数据所有者清楚。
- [ ] Domain 未引用 Infrastructure、UI、数据库、文件系统、网络或平台 API。
- [ ] 未直接调用其他模块内部类、Repository、表或迁移。
- [ ] 跨模块只通过公开命令、查询、端口、契约、事件或只读投影。
- [ ] 无新增循环依赖。

## 复用

- [ ] 权限、路径、哈希、传输、同步、垃圾桶、保护、审计等核心逻辑未被复制到入口层。
- [ ] 已复用现有用例、契约、SDK或公共组件；无法复用的原因已说明。
- [ ] 没有新建无边界 `common`、`shared`、`utils`、`helpers` 或 God Service。
- [ ] UI 只保留平台展示逻辑，不承载领域状态机。

## 技术栈

- [ ] 未引入未经 ADR 批准的新语言、框架、运行时、数据库或基础设施。
- [ ] 新依赖有必要性、许可证、安全、跨平台、包体和退出策略说明。
- [ ] 生成契约与 SDK 未被手工修改。

## 可靠性

- [ ] I/O 有取消、超时、幂等/重试边界和结构化错误。
- [ ] 长任务有 task/plan/transfer ID、检查点与部分成功语义。
- [ ] 文件安全、权限和性能影响有测试证明。

## 交付

- [ ] `architecture_review` 已填写且与 diff 一致。
- [ ] 架构测试、契约测试与相关 CI 门禁通过。
- [ ] 技术债有任务 ID、所有者和到期条件。
