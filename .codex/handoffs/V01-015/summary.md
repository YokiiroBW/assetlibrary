## 集成与优化

- V01-016 把已有账号/会话/管理员状态机接入受保护部署授权和同源 HTTPS，口令风险策略不被跳过；V01-017 将库、索引、扫描请求和任务接入各自 PostgreSQL schema；V01-018/020 完成 Web 和真实浏览器闭环；V01-019 交付自包含 Windows 运行包。
- Host 负责配置、DI、TLS、传输、后台消费者和生命周期，不复制核心权限、路径或任务逻辑。真实文件探测与枚举在读取配置/DB/secret 前分派至同一二进制的独立只读 Worker；有界协议、超时、取消、退出检查和 Windows Job 保证异常不能被当成扫描完成。
- 修复真实组合暴露的问题：NOINHERIT 查询连接显式 SET LOCAL ROLE；HIBP 数据增长和无末尾 CRLF 的合法响应兼容；Windows TLS 私钥加载和正常释放；新旧证书下持久密钥解密；Web 当前浏览结果优先更新离线状态。
- 扫描提交受 lease/fencing/每库独占保护，以已提交 snapshot 事实修复响应或 journal 丢失；首次成功后明确拒绝伪重扫。迁移14–18追加，1–13未改。
- Windows 包从单个干净 Git 快照构建 Host/Web/SQL/脚本，私密状态和独立数据库不与资产重叠，包哈希/进程身份反复核验。正常退出先请求 Host 释放资源，超时才对已确认自有实例强制回退。

## 模块、契约与兼容性

未新增主语言、框架、数据库、重大依赖或微服务。复用既有 AssetLink 契约生成、GatewayAuth 策略/投影、InitialReadOnlyScanService、TaskHealth 和迁移/发布工具。跨模块仅访问公开端口，Infrastructure 不反向渗入核心；测试的 Host 内部入口只用于受控外部 transport，没有运行时安全绕过开关。

默认健康宿主兼容；显式 `--read-only-trial` 才开启试用，数据库和各模块最小权限就绪检查是硬前提。资产写入始终 false。新的机器 Alpha 状态把认证/DB/API/TLS标为有试用证据的 component_only，保留原有发布阻断；新回归拒绝把它们改为 passed 或删去 E2E 证据。

## 已知限制与残留

首次管理员/恢复/改密需要风险源联网，已有账号登录/读取可离线。部署包只支持本机浏览器；需要操作者手动信任证书并按说明续期/保留旧解密证书。正常停止已验证自身密钥容器不增长，强制结束的Windows密钥容器可能残留；不删除不明系统密钥。

自动批准审查拒绝删除本轮两处合成目录，仅返回 blocked by policy，操作未执行且未换途径重试：V01-017旧失败ACLfixture已恢复Deny规则，保留17字节合成文件；实际SMB验证目录已恢复assets路径并保留。精确路径见 [扫描交接](../V01-017/summary.md) 和 [SMB证据](../V01-017/smb-verification.json)。历史ALIGN-002还保留9个空目录。Git clean只说明受版本管理工作区无待提交修改，不表示磁盘无缓存、产物或残留。
