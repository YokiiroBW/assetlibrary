# Windows 原生入口冷启动对照计划（用户已确认，执行前核验中）

## 已有证据

- 官方原版组件独立绑定成功，真实 Explorer 打开仍出现无关联应用。
- 实机 GetAttributesOf 请求 FOLDER 时成功返回不含该位；同注册、相同 PIDL 完整字节、同掩码的两个独立进程均稳定返回 FOLDER。枚举优先与解析优先的 46 次查询都成功，输入指纹不变。
- 原始 UPDATEDIR 与追加 ASSOCCHANGED 都完成了受控实测，仍未修复入口。通知返回不等于所有共享缓存已经重建。
- 独立测试窗口的新进程并不等于桌面 Shell 与其共享状态完成冷启动。至今没有重启原用户 Explorer。

因此，下一对照用于区分长期运行的 Shell 状态与持久环境/注册问题；尚不宣称缓存就是根因。

## 需要确认的影响

测试前、清理后各重启一次当前用户会话的 Windows Explorer。原有文件夹窗口会关闭，任务栏和桌面会短暂重载。执行前必须确认没有进行中的复制、移动、重命名或其他文件操作。不会把只关闭测试窗口等同于这项授权。

不承诺自动恢复原文件夹窗口布局。Chrome、Codex、NAS 服务及资产文件不属于停止或修改对象。

## 确认后的具体流程

1. 重新核对活动会话、当前用户、系统 explorer.exe 路径、进程创建时间及调试状态；不使用历史 PID 直接停止进程。若身份不符、会话不可用或存在未确认的调试/文件操作，暂停执行。
2. 复用已核哈希的官方 F298 DLL 与双通知 323CD843 守护器，只登记原四个独占 HKCU 根；HKLM、系统策略及默认关联值保持原状。
3. 重启当前用户的 Explorer，确认新的桌面 Shell 正常运行。另建独占测试窗口，重新取得身份和“此电脑”正控。
4. 在注册有效期内检查入口是否出现，并执行一次打开；必要时使用已审查的单属性观察器记录相同请求掩码的实际结果。不得通过改写属性或返回值制造成功。
5. 完成调试器脱离和测试窗口清理，撤销四个临时根，核对双通知及不存在读回。再次重启 Explorer，确保本次测试可能载入的 DLL 不继续留在原用户 Shell 进程中；确认桌面和任务栏恢复。
6. 保存前后进程身份、同条件入口/属性结果与清理证据。一次冷启动对照不能代替 G1..G4、20 次恢复循环或 8 小时稳定性验收。

## 当前状态

只完成只读进程快照和计划编制。尚未停止任何原用户 Explorer，也未执行冷启动。快照仅作准备，不是可直接复用的执行目标。
