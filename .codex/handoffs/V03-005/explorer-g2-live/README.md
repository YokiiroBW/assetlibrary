## 保留的失败与限制

- 07最初工具F5键调用未产生管道请求；点击原生刷新按钮才触发。此轮证明的是实际按钮路径，不能据单次工具键输入归因于产品键盘故障。
- 原冻结契约要求Host重启后重开根。07单次Refresh显示Loading，不计自动恢复；重开后的真实Ready才计成功。同视图刷新体验仍待改善，V03-013的公开通知机制实验未取得等价视图，不修改DLL行为。
- 07的invalid恢复截图已显示真实库，但原生取证晚于自动注销、expectedPathParse失败，原始失败保留；该项关闭依据为08补测。
- 08最后原生恢复完成至原期限的精确差约48.48秒（48.479821秒），未满足执行计划预留60秒。原operator总结中的48.37来自舍入，保留原件并在此纠正。注销由原600秒期限触发，稍后的stop标记不是原因。这是执行计划偏差，不能改写为G2的新退出标准，也不因此重复成功验收。
- crash是协议边界上的故障进程异常退出模型，不声称已覆盖任意真实AssetHost内部崩溃原因。原生进程可能因Shell/COM引用继续驻留；没有宣称全部COM对象已释放或DLL卸载通过。

源代码与二进制采用此前已验收版本：Shell来源4e3f6bb、Host来源12618ca；故障工具来源d3b2ba3、集成88e6c21。本轮未改运行时DLL/Host/协议。调用方身份、40B/20B写入、实际视图、恢复、清理与原始失败均逐项复核，门禁原exit_criteria保持不变。
