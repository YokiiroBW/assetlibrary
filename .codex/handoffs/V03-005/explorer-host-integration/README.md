# Windows Explorer 与真实 Core 接入验收

状态：本次受控只读接入的真实 Explorer 功能验收通过。原生侧栏入口、冷加载、同窗口目录、分页、后台服务不可用、重启后的旧位置拒绝与根恢复均已验证。完整 Windows 首版、正式安装与 G2..G4 仍未完成。

## 本次实现

AssetHost 复用既有 HTTPS 登录、Cookie/CSRF、ReadOnlyClient 和生成 SDK。C++ Shell 只通过受限本地管道读取授权快照，使用原生 DefView、目录打开命令和系统图标。每页最多 100 个真实条目与一个明确的下一页导航项；真实路径、权限和分页查询继续由 Core 处理。没有新增外部依赖、数据库、HTTP 业务接口、资产写操作或进程内媒体处理。

## 已确认的结果与修复

- Host 普通测试最终 57 项通过；2 项真实 Core 组件测试在后续管道/计时修正前通过，其不变的会话/查询输入未重复计数。C++ 协议、PIDL、150ms 等待预算、取消、默认命令和图标检查通过；最终呈现状态修复的四项受影响 CTest 通过。
- 真实原生 Host 与 C++ 进程互通得到根 1 项、库第一页 101 项（100 条目加下一页）、第二页 38 项、子目录 1 项。
- 首次互通暴露已关闭管道没有正确复位，导致快速失败循环。原始 33,832,359 字节日志保留在 runtime；新增原生读完即关闭反例在旧实现 98ms 内捕获 5,232 次错误，修复后连续 64 次连接零错误。服务器现在复位已接受连接，停止不可恢复的接受失败，并限制错误重试及日志频率。
- 第一次 GUI 显示真实库，但双击未导航；补齐仅限目录与分页的默认打开命令和系统文件夹图标。第二轮同一 Explorer 窗口实际进入 88 字节子 PIDL，证明目录打开修复有效。
- 后续冷页面仍停留在 Loading。真实进程内两份稳定诊断证明：callback 的站点/窗口/线程挂接成功，但关联的 clone Folder 从未枚举，依赖其状态通知无法启动刷新。最终改为检查实际 IFolderView 的首项 PIDL，只有已显示的 Loading 才刷新；正常项/错误停止，0项仅有界观察。保持500ms、10秒/20次、4活动视图及Core有效期，不广播其他视图状态或放宽授权。

## 最终真实窗口结果

最终Shell集成源 `4e3f6bb`，DLL SHA256 `FA0F657A66F922DE1ED7A0C6A8E3E9635C2D6D0DDE59B355177DF60C34742C85`；Host源 `12618ca`，DLL SHA256 `D26CA4310D7469D7837F2C5D28E14CD12A110C85ADAAD79349A55950310C5A8E`。

- 无预热、无F5辅助初次加载：真实库1项 → 首屏101项（100条目+下一页）→ 下一页38项 → 相册1个夏日目录 → 夏日1个文件。均通过正常原生导航及实际4FF视图/PIDL/数量/名称读回；文件未打开。
- 正常停止Host后，导航显示不可用；重新启动Host后，一次明确的负路径F5拒绝旧epoch位置，再打开根目录自动恢复真实库。它不算初次加载预热。
- 新自有目标进程与同窗口导航得到核对。加载完成只按观察时间上界记录，不用稀疏截图宣称实际小于10秒，也不据此关闭G3性能门禁。
- 600秒原生guard于期限自动注销，不能写成稍后stop标记触发；独立9字段missing、Desktop32项和入口消失、两个Host退出、所有自有窗口关闭均已确认。原用户Explorer未重启或强杀；原目标/启动进程可能仍驻留，不宣称全部COM卸载。
- 三轮Core支架均已最终关闭，分别核验138个合成文件的强hash/mtime未变、临时数据库与6个账号回收、监听器/进程退出与私密runtime删除。

最终本机运行证据位于 `.runtime/explorer-host-integration/desktop-05`，原始截图位于其 `screenshots`；[第五轮证据索引](final-cycle/evidence.json)保存可审阅结果及来源hash。
