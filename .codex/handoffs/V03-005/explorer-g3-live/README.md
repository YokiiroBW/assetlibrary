# G3 真实 Explorer 量测验收

2026-09-12，G3按原退出条款与[测量前冻结的口径](../../../../docs/decisions/2026-09-12_G4用户豁免与G3验收范围.md)通过。G1/G2/G3为实测通过；G4依用户要求豁免，20轮/8小时没有执行，不能写成实测通过。完整客户端的安装登录、预览等功能另行跟踪。

## 实际结果

同一目标Explorer PID16068、创建时间134336932049894842、同一DLL路径/SHA/映射和累计计数，完成五次silent故障、取消回收与正常Host重开根恢复。工具操作较慢，分成两个独立600秒登记周期，仍保持进程与计数连续；没有重复成功样本或延长guard。

## 改变了什么

量测只记录固定内存数字与QPC，不加入文件/网络日志、通用监控框架或Explorer测量线程。新增私有诊断pid2，原pid1不变。修正操作回收计数的顺序：`delete Operation`完整结束缓冲、句柄和存储后再减少active；DLL pin保留至这些代码执行完毕，同步路径最后交还，异步路径仍由FreeLibraryWhenCallbackReturns交还。业务、150ms等待、四操作上限、初始500ms/10秒刷新及Core缓存策略不变。

实现来源87a882a、集成4ba8d31；新Shell DLL SHA256 `4AE3477602D7DDF15659A9C86C17C443630A986A933C6803CE17FF00C15184A5`。严格构建、六项受影响CTest及仓库架构/契约检查通过；真实运行由两个登记周期完成。

## 准确保留的边界

- `defer_n=0`：本次取消都同步确认后回收，没有测得异步延后回收时长，不为制造该分支增加假延迟或伪造完成事件。
- pins为本组件保活与交还记录，归零不等于Windows已经卸载DLL；窗口关闭后Explorer进程可能仍驻留。没有强制额外Release、终止或重启用户Explorer。
- 旧1ms WM_NULL点观察因ready输出耗时用尽窗口而产生零样本，标为inconclusive，不计通过。辅助观察器已修正为至少一次真实采样，空样本不能成功；原件与失败保留。
- 两个30秒WM_NULL区间各276次、零失败，最大7.6903ms，但03区间结束早于故障Query开始1.4759763秒；05区间开始晚于Query结束0.4921243秒，且结束早于重开观察3.2646541秒。因此只作为前后事件循环响应佐证，不能称覆盖故障或恢复期间。G3主结论来自内部QPC。
- 150ms是代码中的逻辑等待预算，不能将161ms整体返回写成≤150ms；2秒回收和10秒恢复是本次事先冻结的测量定义，不是原G3已经给出的数值或所有网络的产品SLA。
- 本次只有五个G3样本，没有G4的20轮/8小时；同视图一次Refresh停在Loading的既有体验限制未在本轮修复。

两段注册均按owner规则清理、独立九字段缺失；第一段按原期限自动注销，第二段提前显式停止。所有自有窗口、Host/fault/observer和Core测试服务已清理；原Explorer身份未变，138个合成文件hash/mtime不变，6个临时角色回收。事件日志在记录时段读取成功且无Application1000/1001/1002记录。
