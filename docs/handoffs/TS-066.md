## 1. 目标与交付物

`POST /assetlink/v1/dedup/{start|status|results|cancel|revalidate|export}`。

## 7. 风险与技术债

1. **报告保留是进程内的**：`DedupReportRegistry` 有界保留 8 份报告（每份 ≤20000 项），服务重启后报告
   不再可读。这是本卡明确的设计取舍：不新增迁移、不新增持久表，边界以契约里的 `RetentionBoundary`
   如实告知前端与用户，页面在报告缺失时显示「本次结果已不可读取」而不是空结果。若后续要求跨重启可读，

只用六个已授权操作，没有任何路由桩：

| 步骤       | 驱动方式                                        | 断言                                                                                     |
| ---------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 未登录拒绝 | 无 Cookie 直接 POST 六个操作                    | 每个都 401 `authentication_required`，且答案里不含它命名的库/任务                        |
| `start`    | `POST /dedup/start`（库 + 操作键）              | 受理即 `queued`/`leased`、`report_available=false`、版本名为空                           |
| `status`   | 轮询 `POST /dedup/status`                       | 等到 `report_available=true`，版本等于 `{task_id}:1`，重复组数 > 0，计划状态非空          |
| `results`  | `POST /dedup/results`                           | 页自带 `analysis_version`，`total>0`，重复组**两个成员**都在                             |
| `revalidate` | `POST /dedup/revalidate`（先回执后轮询）      | 回执 `pending`，随后 `completed`、`plan_still_current=true`                              |
| `export`   | `POST /dedup/export`（带版本 + 摘要）           | 版本一致、`grants_file_operation=false`、组数 > 0；换一个版本号导出 → 409 `dedup_version_conflict` |
| `cancel`   | `start` 后 `POST /dedup/cancel`                 | 取消被记到持久任务上，任务落终态，且**取消不产生任何报告**                               |
| 重启后     | `host.RestartAsync()` 后读同一 `task_id`        | 重启**前**先断言报告可读且 `total>0`；重启后同一 `task_id` 仍在（任务在 TaskHealth）、状态不变、`report_available=false`；`results` 返回 `dedup_report_not_retained`、`groups` 为空、`total=0`；再 `revalidate` → 404 `dedup_report_not_retained` |
| 只读       | 结束时逐个文件比对 SHA-256 与 mtime             | 两个合成库的每个文件**一个字节都没变**                                                                 |
| 真实租约   | `DedupTrialLeaseReader`：以模块自身会话只读 `task_health.durable_task` | 认领后 `state=leased`、`lease_owner=trial-dedup`、`lease_generation>0`、租约窗口未过期；**在仍持有租约时**两次采样之间 `heartbeat_at` 前进且 `lease_until` 越过认领窗口；`cancellation_requested_at` 在取消前为空 |
| 取消运行中 | 第二个操作键 `start` → 确认 `leased` → `cancel`  | 取消请求被记到持久任务（`cancellation_requested_at` 非空），终态必须是 `cancelled`（**`succeeded` 会判失败**），且不产生报告 |
| 浏览器闭环 | 真实 Chromium 打真实 Core（无路由 mock）        | 管理员登录 → 选库 → 开始分析 → 状态/结果（重复组两名成员、开合详情后焦点回到该行）→ 导出计划（文档 `grants_file_operation=false`、版本与页面所报一致）→ 重新核对（`来源未变化`）→ 第二个库开始分析并在运行中取消（页面 `已取消` 且「本次分析没有可读取的结果」）；页面调用的六个操作从线路逐一核对 |

租约续期为什么要直接读存储：worker 只在一次尝试**超过一个心跳间隔**时才续租，而合成源在本机
文件缓存下 130 ms 内就读完，从 HTTP 面观察「续租」只能是时序巧合，且终态任务的 `updated_at` 前进
只说明它结束了。因此本轮改为：合成库按**每个库各自一份**填充文件隔离（不再共享根目录，注册也会
拒绝重叠根），试运行自身把心跳间隔设为 100 ms，然后用模块自己的会话在**任务仍为 `leased`** 的两次
采样之间比较 `heartbeat_at` 与 `lease_until`。这不是测试后门：产品侧没有加任何钩子，读到的是
`task_health.heartbeat_durable_task` 真实写下的列。第二轮曾声称有一个 `DedupTrialLeaseProbe` 按名字
驱动租约生命周期——**该文件不存在，本轮已删除该说法**（文件数 646 → 645），上表是本轮真实做的事。

浏览器流程里导出排在重新核对**之前**：落一次复核会让服务端把复核自己的报告作为该库结果的新版本
落盘，页面此时仍持有它读到的那一版，再导出就会被 409 `dedup_version_conflict` 拒绝。顺序调整是
试运行对真实行为的适配，页面本身未改；「复核后页面不重载新版本」这一既有行为已单列为缺口，见第 9 节。

「迟到复核不得覆盖新报告」这一条**在试运行里无法确定性触发**：worker 单线程、按认领顺序串行执行，
一个复核的扫描与落盘之间不会插进另一次分析。因此该竞争用**进程内确定性用例**
`DedupRecheckFenceTests.ALateVerdictNeverReplacesANewerAnalysisOfTheSameLibrary` 覆盖（合成双文件库 +
真实 `DedupJobWorker` + 带围栏探针，在扫描中途发布更新的一次分析、**旧 key 仍保留**），并已用反向探针
确认有效：把 `File` 换回上一轮的非原子写法后该用例立即失败
（`Assert.AreNotEqual 失败。应为: <6499ee26-…> 以外的任意值，实际为: <6499ee26-…>`，即旧复核确实把
`latest` 抢了回去），换回修复后 4 项全绿。两类证据互补，均在交接材料中列出。
