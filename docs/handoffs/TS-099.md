## 2. 本轮实际修改

### R1 形状、身份与布局（消除三处误拒 + 精确模板）

新增两个纯策略文件，把原来挤在 `MediaPackagePolicy.cs`（776 行）里的形状读取与布局匹配拆开：

- `services/core-server/Modules/OperationTrash/Domain/MediaPackageShapePolicy.cs`（新增）
  纯 JSON 形状/类型/身份读取：根对象、`selected_parts[i]`、`files[i]` 三层的**精确键集**（多键与
  缺键都拒）、`cid` 的「显式 null」与「键缺失」严格区分、整数词素、身份词表、UUID 规范小写、
  `BV`+10 位、cid `[1-9][0-9]{0,19}`、staging_ref、sha256、per-file 与 per-kind 尺寸上限。
  所有诊断位置只用固定字段位（`files[2].size_bytes`）或**已通过校验的相对路径**，未校验的原始
  字符串绝不进入 `Issue.Location`。
- `services/core-server/Modules/OperationTrash/Domain/MediaPackageLayoutPolicy.cs`（新增）
  纯布局策略：`layout` + `media_extension` + `selected_parts` → 精确的必需/可选文件模板与基数。
  单集只接受 `video.{ext}` / `movie.nfo` / `source.json` / `poster.{jpg,png}`；多集只接受
  `Season 01/S01E{episode≥2位}-cid-{cid}` 词干派生的 `.mp4|.mkv` / `.nfo` / `-thumb.{jpg,png}`，
  加根级 `tvshow.nfo`、`source.json`、可选 `poster.{jpg,png}`。cid 必须是声明值本身（`cid-10` 不是
  `cid-101`），episode 必须与该 cid 的 `episode_number` 一致，未选 cid 一律拒绝，每个 cid 至多一张
  thumb，`tvshow.nfo` 与 `source.json` 各恰好一次，poster 至多一张。
- `services/core-server/Modules/OperationTrash/Domain/MediaPackagePolicy.cs`（重写为编排层）
  只保留：冻结预算常量、编排 shape→layout→预算、声明字节总量、真实列表比对、服务端目标目录名。
  校验后的清单以**只读快照**构造（`[.. parts]` / `[.. files]`），调用方无法再改已校验状态。

三处误拒已消除并各自被测试固定：根级文件 `cid: null` 被接受、单集 `video.mp4` 被接受、单集不要求
分集 NFO（只要求 `movie.nfo`）。`unknown_field` 在根/`selected_parts`/`files` 任一层都判
`invalid_manifest`。17 个负例与 2 个正例逐条对齐冻结码（见第 4 节静态自查）。

### R2 真实路径边界（Windows 规范根分隔符）

- `MediaPackagePathBoundary.cs`：`TryOpen` 过去把根转成反斜杠再与 `CanonicalLibraryRoot.Value` 的
  正斜杠做 `StringComparison.Ordinal` 比较，导致**每个正常 Windows 根都被判 `unsafe_path@scope`**。
  现在所有比较统一走 `Canonicalize`（正斜杠形式，卷根保留尾分隔符），并沿用 scope 声明的
  `RootPathComparison`；真实文件访问仍用平台原生形式。
- 子路径解析不再无条件拒绝 `Path.AltDirectorySeparatorChar`（Linux 上等于 `/`，会把合法的嵌套多集
  路径全部拒掉）：现在**任何平台都拒绝反斜杠**，Windows 额外拒绝正斜杠，POSIX 平台的嵌套路径正常
  解析。
- 卷根包含判断修正：根为 `C:/` 时其自身后代可被正确判定为包含；`Contains` 同时修掉「共享前缀的
  兄弟目录被误判为包含」。
- 目标对象判定：`TryObserve` 的 `Missing` 与 `Unsafe`/不可访问严格区分——已存在的文件、目录、链接
  或重解析点一律 `target_exists`；**无法观察的目标不再被当成「尚不存在」**。目标父根缺失或不可用
  报 `target_unavailable`，包根缺失报 `source_missing`，两者不再混淆。

### R3 预算真实执行

- `MediaPackageFileHasher.cs`：读到超限过去抛普通 `IOException`，被外层翻成 `io_failure`。现在先按
  真实长度预检，再在流式读取中强制，超限抛
  `MediaPackageBudgetExceededException`（新类型，继承 `IOException`，位于
  `Application/MediaPackageInspectionPorts.cs`），由 inspector 翻成 `budget_exceeded`。
- `IsolatedMediaPackageInspector.cs`：读取前先比较「声明长度 vs 剩余预算」，超限即 `budget_exceeded`，
  不再先读再判；枚举改为**边消费边计数**（不再 `ToArray()` 全量物化），超过 4096 条即
  `budget_exceeded`。
- `MediaPackageInspectionLimits.cs`：`minimumTargetHeadroomBytes < 0` 改为
  `< MinimumTargetHeadroomBytes`，即 64 MiB 是**下限**，受信构造只能抬高、不能压低（`0` 与 `-1` 现在
  都抛 `ArgumentOutOfRangeException`）。1 MiB 流缓冲、32 GiB 读预算、120 s 上限、4096 条枚举上限、
  100 条 issue 上限、1 MiB 清单上限均未放宽。

### R4 读后复核与最终集合复核

- 每个文件读前读后各取一次 `Stamp`（长度 + 最后写入时间），中途被替换/增长即 `source_changed`。
- 所有已读文件在**全部读取结束之后**再次逐一复核（`ReverifyObserved`）：先读的文件在后来文件读取期
  间被改动，不再依赖它自己那一次旧戳记，一律 `source_changed`。
- 结束后再次枚举真实列表与首次列表比对（文件与目录都比），再次确认目标名仍然不存在（并发发布即
  `target_exists`），最后再确认受信根与 scope 仍然有效。

### R5 报告与错误分类

- `Issue.Location` 只承载已校验的相对路径或固定字段位；绝不含绝对路径、换行或原始异常文本。
- `issues_truncated` 端到端保留：`MediaPackageManifestReadResult` 增加 `IssuesTruncated`，reader 把
  sink 的真实截断状态带出，service 的 `Rejected(...)` 不再硬编码 `false`。
- 错误分类修正：离线/过期的 scope 现在报 `target_unavailable`（可用性拒绝），**不再误报
  `scope_changed`**；`scope_changed` 只留给运行中被撤销的授权；预算与 IO 各自报
  `budget_exceeded` / `io_failure`。
- sink 的按 `(code, location)` 去重与 100 条上限继续在记录时强制，诊断存储有界。

#### 一处必须如实说明的断言更正

R5 明确要求修正「Offline → `scope_changed`」这一错误分类。因此两个用例名与断言随产品修正同步更新：

- `OfflineLibraryAvailabilityIsRefusedAsScopeChanged` → `OfflineLibraryAvailabilityIsRefusedAsTargetUnavailable`；
- `ExpiredScopeIsRefusedAsScopeChanged` → `ExpiredScopeIsRefusedAsTargetUnavailable`。

两处都**新增**了 `Assert.IsFalse(Codes(report).Contains("scope_changed"))`，断言比原来更严而不是更松：
它们现在同时证明「必须报 `target_unavailable`」和「不得报 `scope_changed`」。其余 41 个测试方法的断言
逐字未动。这是 R5 指定的分类修正，不是为求绿而弱化断言。
