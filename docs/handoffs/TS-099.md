## 2. 本轮实际修改（11 个文件：5 代码/测试 + 6 文档）

### R1 诊断内部集合的真实上限（唯一生产改动）

`Contracts/MediaPackageContracts.cs`：`MediaPackageIssueSink.Record` 原来**先 `recorded.Add` 再判 cap**：

```csharp
if (!recorded.Add((code, location))) { return false; }   // 插入已经发生
if (issues.Count >= MaximumIssues) { IsTruncated = true; return false; }   // 发现满了，但键已经留在集合里
```

每个**新的不同**问题先进入 `HashSet`，随后发现 `issues` 已满就返回，插入**从不撤销**。实测（cap=1、
10000 个不同 location）：公开问题 1、`IsTruncated=true`，而**内部 `recorded.Count=10000`**——
前一轮的有界内存保证被回退，注释和报告却仍宣称所有内部存储不超过 cap。

现在改为：

1. `if (recorded.Contains((code, location))) { return false; }` —— **纯查询**，重复对不置截断；
2. `if (issues.Count >= MaximumIssues) { IsTruncated = true; return false; }` —— 满则**只标截断**，
   **不向任何内部集合添加键**；
3. 有容量才 `recorded.Add(...)` + `issues.Add(...)`，并维护 `codes`。

内部键数与 `issues` 数均始终 ≤ `MaximumIssues`，顺序仍是首次出现顺序，返回值仍是只读视图，
`Record` 的布尔语义不变（只有真正记录成功才 true），冻结错误码与公开签名未动。类文档同步更正为真实不变量。

### R2 唯一失败的测试：重复路径夹具拼成了非法 JSON

`tests/.../MediaPackageBoundaryTests.cs` 的 `DuplicateDeclaredPathsAreRejectedByTheReader` 原来用字符串替换：

```csharp
text.Replace("\"path\":\"poster.png\"", original + "," + collision)   // 把对象拼进了属性列表
```

得到 `"path":"poster.png",{"cid":null,...` —— **不是 JSON**。reader 以 `invalid_manifest` 拒绝，
`duplicate_path` 断言必然失败。

现在改用 `JsonNode` 数组操作：解析真实夹具 → 在 `files` **数组**里找到原 `poster.png` 对象 →
`files.Add(...)` **追加**一条完整 `Poster.PNG` 对象（沿用原条目的 kind / size_bytes / sha256，`cid=null`）→
序列化 → **重解析**并断言两条路径都在、数组长度只多一条 → 才调用真实 reader 并断言 `duplicate_path`。

**产品未因此调整**：协调已按正确输入独立确认产品会返回 `duplicate_path`。

### R3 转义回归必须核最终 JSON 原始字节

`tests/.../MediaPackageContractTests.cs`：原用例把**文字** `\uD800` 交给 `JsonNode` 再序列化，序列化器把
反斜杠再转义一次，最终字节是 `5c 5c 75 44 38 30 30`（转义反斜杠 + 字母 u），**不是**真正的代理转义
`5c 75 44 38 30 30`；因此旧断言只能写「任意冻结码」，字段级拒绝（`invalid_identity` / `invalid_path`）
可以冒充语法守卫。

现在新增 `MutateWithRawEscape(exampleName, mutate, rawEscape)`：变异体写入唯一 ASCII 占位符
`zzRawEscapeSlotzz` → 正常序列化 → 在**最终字节**里把占位符替换为真实转义（占位符缺失即硬失败）。

- 每个反例**先断言字节形状**（最终字节必须含真实单反斜杠转义），再断言精确诊断：
  `invalid_manifest` + `surrogate_escape`，且**不得**出现字段级码；覆盖 bvid 值、文件 path、
  **属性名**三处 × `\uD800XDC00` / `\uD800` / `\uDC00` 三种写法；任何框架异常外逃即失败。
- 合法 `\uD83D\uDE00`、直接 UTF-8 的同一字符、转义反斜杠后文字 `uD800` 是**三个真实不同的字节样本**：
  断言三者互不相同、都不报 `surrogate_escape`，且合法 pair 与 UTF-8 写法给出**同一**字段语义诊断
  （`invalid_identity@bvid`）。原始摘要按**最终字节**重算。

**未把原生 `MediaPackageManifestReader` 改回扫描器**：它本轮独立真实反例已通过。

### R4 固化「目标根在读取中变成文件」
