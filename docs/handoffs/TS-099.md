## 2. 本轮实际修改（15 个文件）

### R1 冻结集节目录（`Season 01` 是合同常量，不可由输入推导）

`Domain/MediaPackageLayoutPolicy.cs`：删除 `EpisodeDirectory(IReadOnlyList<MediaPackageFileEntry>)` 与
`IsEpisodeEntry`，新增 `internal const string EpisodeDirectory = "Season 01";`；
`ValidateFiles` 改为 `var episodeDirectory = layout == MediaPackageLayout.Multipart ? EpisodeDirectory : string.Empty;`；
`TryReadEpisodeStem` 用 `episodeDirectory + "/" + EpisodePrefix` 作为期望前缀（不再有空目录特例）。

为什么必须固定：`contracts/media-package/candidate-v1/semantics.md:22` 钉死了 `Season 01/` 这条路径。
上一轮「从声明的分集条目推导目录」等于让输入自己定义模板，于是**全部**分集统一移到 `Season 99/`、
或全部去掉 Season 目录的包都被接受——这正是预检要防的事。现在这三种情况都逐条 `invalid_file_set`
（自定子目录另记 `invalid_path`）。

### R2 目标受信根必须是可观察目录

- `Infrastructure/MediaPackagePathBoundary.cs`：新增 `TryObserveDirectory(string resolved, out MediaPackagePathFault fault)`，
  三态语义——`null` 表示不可观察，`false` 表示观察到**普通文件**且 `fault = None`，`true` 表示目录。
  必须这样分开，因为 `Directory.Exists` 对「这里是文件」和「这里什么都没有」**都返回 false**。
- `Infrastructure/IsolatedMediaPackageInspector.cs`：新增
  `RequireTargetParentDirectory(MediaPackagePathBoundary targetBoundary, string location, int enumeratedEntries = 0)`，
  在**首次读取前**（`RequireTargetParentDirectory(targetBoundary, targetName)`）与**最终确认时**
  （`RequireTargetParentDirectory(reopenedTarget!, "target", confirm.EnumeratedEntries)`）各调用一次。
  目录通过；普通文件走 `FaultCode(Unsafe)` → `unsafe_path`；`Missing` → `target_unavailable`。

上一轮 `TryObserve` 对普通文件返回 true，于是「目标受信根被换成普通文件」被判 `Inspected`，
且普通文件还可能被读成「目标还不存在」而报 `target_exists`。现在不会。

### R3 JSON 解码守卫改用原生 token/解码能力

`Infrastructure/MediaPackageManifestReader.cs`：**删除**手写字节扫描
`HasWellFormedStringTokens` / `HasWellFormedEscapes` / `TryReadEscape` / `HexValue`，改为
`TryDecodeEveryString(byte[] raw)`：用 `Utf8JsonReader` 遍历文档，对每个 `PropertyName` 与 `String`
token **实际调用 `GetString()` 完成解码**，捕获 `InvalidOperationException` 即返回 false，
调用方记 `invalid_manifest@surrogate_escape`。

为什么必须改用原生能力：旧扫描用 `marker + 6` / `marker + 11` 的固定偏移读下一段转义，
既**漏掉** `\uD800XDC00`（没有要求低位代理必须以 `\u` 开头），又**误拒**合法成对 `\uD83D\uDE00`。
改为让解析器自己解码后：同一个字符无论写成 UTF-8 还是写成合法转义，在语法层行为**完全一致**；
字段是否允许某个字符由身份/布局校验决定，语义归语义层。不新增 JSON 解析器、不新增文件、
不对整个服务加宽 catch、不回显原生异常或原文。

### R4 去重先于 cap；撤回公开端口上的内部状态

- `Contracts/MediaPackageContracts.cs`：`MediaPackageIssueSink.Record` 改为**先查有界去重集合**再判上限。
  重复的 `(code, location)` 不再把 `IsTruncated` 置 true（它没有丢弃任何诊断）；只有**新的不同**问题
  因容量被丢弃才置 true。去重集合只存已记录的键，所以内部记录仍 ≤ cap，顺序仍是首次出现顺序，
  返回值仍是只读视图。类文档同步更正。
- `Application/MediaPackageInspectionPorts.cs`：**撤回**公开 `MediaPackageObservedFile` 上新增的可空
  `Stamp` 参数，恢复为 `(string Path, MediaPackageFileKind Kind, string? Cid, PayloadFacts Payload)`。
- `Infrastructure/IsolatedMediaPackageInspector.cs`：mtime 复核数据移入**私有**
  `private sealed record ObservedFile(MediaPackageObservedFile Entry, (long Length, DateTimeOffset ModifiedAt) Stamp);`，
  `PackageLoad` 用 `IReadOnlyList<ObservedFile>`，对外只投影 `file.Entry`。
  等长改写仍能被发现，但公开端口形状不再被内部记账污染。

### R5 测试构造与断言修正（全部在测试侧，6 处，无一处放宽）

1. `MediaPackageBoundaryTests.DuplicateDeclaredPathsAreRejectedByTheReader`：原来只在原地把

   `Assert.ThrowsExactly<OperationCanceledException>` 要求**精确基类**，而 awaitable 实际抛派生类

3. 超清单字节预算用例：期望 `ResolveCalls == 1` 与「预算在授权前判定」矛盾，改为 `== 0`。
4. / 5. 两个读预算用例基准误取**单个 video** 大小，而额度是**跨整包**消耗的；改为
   `example.Payloads.Values.Sum(payload => (long)payload.Length)`（少 1 字节用例同样改）。
6. `EnumerationBudgetIsEnforcedWhileWalking`：原强置 `IssuesTruncated == true`，但 4096 枚举上限
   只产生**一条** `budget_exceeded`，没有任何诊断被丢弃；改为 `Assert.IsFalse`，诊断截断另有专门用例证明。

`MediaPackageFailureTests.cs:381`（目标受信根被换成普通文件）的拒绝断言**逐字保留**，
