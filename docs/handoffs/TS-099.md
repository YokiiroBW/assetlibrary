### R4 等长修改复核与实际读取预算

- `Application/MediaPackageInspectionPorts.cs`：`MediaPackageObservedFile` 增加可空
  `(long Length, DateTimeOffset ModifiedAt)? Stamp`。
- `Infrastructure/IsolatedMediaPackageInspector.cs`：`ReadAndRecheckAsync` 回传长度与最后写入戳，
  调用方把它存进观测记录；`ReverifyObserved` 在长度相同的情况下再比一次戳记，因此**等长改写**
  也会被判 `source_changed`。
- `Infrastructure/MediaPackageFileHasher.cs`：每次读取按剩余额度裁剪；额度用尽后探读 1 字节，
  仍有数据即抛 `MediaPackageBudgetExceededException`（不再被翻成 `io_failure`）。

### R5 脱敏、正确错误与有界诊断

- `Infrastructure/IsolatedMediaPackageInspector.cs`：`TargetCapacityRefusalAsync` 只返回**一个**码——
  空间未知 → `target_unavailable`；只有观测到真实缺口才 `insufficient_space`。
- `Application/MediaPackageInspectionService.cs`：按 R5 卡文的明确分类实现——`IsAvailable` 只看
  存储可用性（离线/不可用 → `target_unavailable`），`IsCurrent` 看许可是否仍在有效期内
  （到期 → `scope_changed`），`IsCurrentAsync` 看运行中是否被撤权或版本改变（→ `scope_changed`）。
  三者在开头与结尾各判一次，互不合并。
- `Contracts/MediaPackageContracts.cs`：`MediaPackageIssueSink` 有界——`Issues` 返回 `AsReadOnly()`；
  `Codes` 由 `HashSet<string>` 改 `List<string>` 并以 `IReadOnlyList<string>` 只读暴露；
  达到上限即置 `IsTruncated = true` 并在触碰去重表**之前**返回。

### R6 孤立代理 JSON 转义具名拒绝

`Infrastructure/MediaPackageManifestReader.cs`：在取出**任何**成员名或值之前，先按**原始 JSON 字节**
扫描每个字符串 token 的 `\uXXXX` 转义（`Utf8JsonReader` + 自写的精确扫描：反斜杠奇偶性决定该 `\u`
是否真的是转义；高位代理必须紧跟其低位代理，孤立半对拒绝）。命中即记
`invalid_manifest@surrogate_escape`，**异常类型与原文都不进报告**。

为什么必须这样做：这类清单是**合法 JSON**、能解析成功，但**读它的任何字符串都会抛
`InvalidOperationException`**（`JsonReaderHelper.TryUnescape` → `ReadIncompleteUTF16` / `ReadInvalidUTF16`）。
因此判定不能建立在「先读出来再检查」之上——读出来这一步本身就是抛异常的那一步。
