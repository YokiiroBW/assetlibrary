# Windows Explorer 只读浏览版交付

2026-09-12，`0.3.0-preview.2`，Windows 11 x64。主入口为原生资源管理器，连接设置是辅助窗口。此包是可安装的只读浏览预览版，不代表完整 V0.3 发布。

## 安装和使用

本机包：`.runtime/releases/windows/AssetLibrary-0.3.0-preview.2-win-x64.zip`，155,391,746 字节（约 148 MiB）。源码提交 `c25689371b07e84499a13274da4b088a58d4a789`。

SHA256：`340d1e748fc713f8b8506fb686c79acaeab9a821ad7eb1cb38accd6a2e2a69b4`。

1. 完整解压 ZIP，保留 `payload` 和 `manifest.json`，双击 `AssetLibrary.Setup.exe`。不需要管理员权限。
2. 在连接设置中填写自己的 NAS HTTPS 地址、账号和密码；自签证书使用管理员提供的可信 SHA256 指纹。记住登录默认关闭。
3. 在资源管理器左侧打开“资产库”。双击进入资源库和物理目录，通过“下一页（导航）”翻页。
4. 再次打开设置：在资产库内容区域空白处右键 → 显示更多选项 → 连接设置。小窗口可向下滚动到登录按钮。
5. 卸载：Windows 设置 → 应用 → 安装的应用 → 资产库 Explorer 只读浏览 → 卸载。被 Explorer 占用的版本会明确列为待清理；不要强行删除 DLL。正常退出相关会话、释放占用后，可再次运行解压包中的安装器完成卸载清理。

验收机器已经安装 preview.2。测试账号已退出、测试连接配置已移除，测试窗口、后台会话和临时服务已结束；下次打开连接设置会按需启动后台。内部失败候选 preview.1 已注销，但旧 DLL 仍被 Windows 持有，记录为待清理；未结束或重启用户原有 Explorer。

## 验收结果

- 实际普通用户安装后，原生 Explorer 侧栏出现“资产库”，生产 DLL 从正式版本目录加载。
- WinUI 设置窗口实际打开；从 Explorer 右键菜单启动的 Settings 进程父进程是本次专用 Explorer。重复启动保持单实例。
- 通过正式本机控制 API 连接真实 Core + PostgreSQL + HTTPS 合成夹具；实际 Explorer 显示资源库、100 个条目加分页入口、第二页 38 个条目，以及“相册 / 夏日”中文目录和文件名。
- 同一根窗口退出后自动清空，重新登录后自动恢复；子目录退出后回到根并清掉当前面包屑和文件行。后退到历史位置也不能重新读取旧文件。Windows 自己保存的导航历史没有被清除。
- 最终构建通过 77 项 Windows 测试、23 项安装测试、9 项 CTest、6 项打包测试、8 步最终安装 EXE 沙箱生命周期、16 项发行锁测试。真实 Core 客户端 2 项集成测试通过；依赖/许可证/漏洞与仓库架构、契约校验通过。
- 临时服务完成清理，138 个合成文件的强哈希与修改时间未变，6 个临时数据库角色已移除。没有修改 NAS 资产。

## 保留的限制

- 未签名预览包；SHA256 证明完整性，不是发布者签名。
- 本版仅目录和文件信息浏览，不含内容预览、下载、上传、同步或文件写操作；NAS 图片 Worker 的平台阻断仍独立存在。
- 部分子目录标签标题显示内部解析标识；友好中文面包屑、文件名与目录导航正常。后续限定名称格式请求的修复单独验收。
- 登录表单的实际人工填写、提交，以及 Windows“安装的应用”页面的卸载按钮未由自动化操作；登录/退出使用正式控制 API 完成，最终 EXE 的卸载逻辑有沙箱实跑和同实现内部候选的真实注销证据。不要把这些替换为完整手工验收声明。
- G1/G2/G3 沿用各自已测证据；G4 按用户明确要求豁免，未进行 20 轮或 8 小时测试。长期稳定性、签名、完整 V0.3 和 Android 真机门禁不随本包关闭。
