# V0.1 Alpha readiness

## 当前结论

**首个 Windows x64 Web 只读试用已集成，完整 V0.1 Alpha 发布仍为 blocked。** 试用的范围、启动方法和实际证据见 [只读试用交付](READ_ONLY_TRIAL.md) 与 [V01-015 交接](../../.codex/handoffs/V01-015/summary.md)。

机器事实源为 `eng/v0.1-alpha-readiness.json`。认证、数据库组合、业务 API、TLS/secret 已从“缺失实现”更新为 `component_only`：这表示它们在限定试用中完成了集成和实测，仍不足以满足完整产品发布。政策没有新增 `passed` 能力，没有关闭 release target，V01-008 继续为 partial。六个试用任务及其交接成为强制审计输入。

```text
python -I -B scripts/validate_v0_1_alpha.py
python -I -B scripts/validate_v0_1_alpha.py --require-ready
```

默认审计必须返回 0，输出 `ALPHA_INTEGRATION_AUDIT_OK decision=blocked`；要求发布就绪时返回 3。证据漂移、政策损坏或门禁执行异常返回 2，不能作为正常阻断通过。

## 完整 Alpha 仍缺少的能力

| 能力 | owner / 后续任务 | 当前缺口 |
| --- | --- | --- |
| 生产认证与公开部署 | gateway-auth-owner / V01-AUTH-RUNTIME | 试用只验证本地账号与本机浏览器；公开、多端部署需要独立验收 |
| 全平台数据库与业务 Host | database-migration-owner / V01-DATABASE-RUNTIME；web-gateway-owner / V01-READ-HOST-INTEGRATION | 已有试用组合，但完整管理功能和各发行平台生命周期未完成 |
| TLS、部署 secret 与更新 | server-packaging-owner / V01-TLS-SECRETS | 有受控本地证书/持久密钥及手动续期；自动证书、升级和异常终止残留处理未闭环 |
| 标签、评分与颜色 | metadata-sidecar-owner / V01-METADATA-CORE | 共享元数据写模型与审计用例尚未实现 |
| 精确查重 | search-dedup-owner / V01-DEDUP-CORE | 生产强哈希证据及权限过滤查询尚未实现 |
| 软件备份与恢复 | backup-update-owner / V01-BACKUP-RESTORE | 迁移备份和停机复制说明不能替代产品级备份、逻辑恢复与升级回滚 |
| 生产文件操作 | operation-trash-owner / V01-WRITE-DURABILITY-GATE | 耐久文件系统适配器、恢复、锁/冲突/空间/校验/审计/垃圾桶的真实闭环仍缺失 |

预览、Provider、增量/通用重扫及完整客户端管理面也未由本轮实现。不得把首次扫描成功当作实时同步完成。

## 外部环境门禁

| release target | 开放 gate | 必需证据 |
| --- | --- | --- |

| large-file-release | M0-006-G1 | release-like 的 1/20/100 GiB 真实字节、容量与故障证据 |

`v0.1-release` 继续受 M0-004-G2、M0-006-G1 和 M0-006-G2 直接阻断，此外还有未完成能力和 V01-008 partial 输入。实际 SMB 测试只切换自有测试目录的可达性，没有断开服务器、共享或网络；未证明 50 万资产长时运行或突然断电耐久性。

## 后续顺序

1. 从已交付只读试用获得真实使用反馈，安排预览和可恢复增量索引；不默认扩展本轮范围。
2. 分别补齐元数据、查重与软件备份/恢复，并提交各模块证据。
3. 生产写入单独通过耐久门禁；容量、SCM、Linux、Docker 在批准隔离环境实测。
4. 只有全部能力、必需任务和 release targets 都通过，才能更新政策为发布就绪。
