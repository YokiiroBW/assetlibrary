# V0.1 Alpha readiness

## 当前结论

V0.1 Alpha 的集成审计有效，但发布判定为 **blocked**。这两个结论并不矛盾：审计通过表示政策清单完整、引用可读、任务状态与门禁事实一致，并且所有缺口均保持阻断；它不表示当前仓库已经形成可发布产品。

机器事实源是 `eng/v0.1-alpha-readiness.json`，审计入口是：

```text
python -I -B scripts/validate_v0_1_alpha.py
```

当前命令应返回 0，并输出 `ALPHA_INTEGRATION_AUDIT_OK decision=blocked`。发布候选入口是：

```text
python -I -B scripts/validate_v0_1_alpha.py --require-ready
```

只要下列任一能力、任务输入或 release target 未通过，该命令就必须返回 3。审计文件损坏、证据漂移、gate ledger 无效或 gate 子进程异常返回 2；这两种失败不可互换。

## 已验证的组件基础

以下结论仅覆盖各任务交接中已经验证的组件边界，不应扩张为端到端产品能力：

| 能力 | 证据任务 | 已验证边界 |
| --- | --- | --- |
| 构建与依赖底座 | V01-001 | 固定 SDK、锁定依赖与原生质量门禁 |
| AssetLink 生成 SDK | V01-002 | 版本化契约及 .NET、TypeScript、Kotlin 生成物 |
| PostgreSQL 迁移底座 | V01-003 | schema 所有权、迁移清单及迁移级恢复保护 |
| CoreServer PostgreSQL 就绪组件 | V01-010 | 显式环境配置、只读 auditor、启动 preflight、运行中 readiness 及 PostgreSQL 16 / bootstrap / ledger 精确核对；不应用迁移、不包含认证或业务 API |
| GatewayAuth 本地认证与会话组件 | V01-011 | PBKDF2 本地凭据校验、持久有界退避、仅摘要落库的服务端 session/CSRF、凭据与主体版本失效、撤销及 OIDC 会话签发边界；不包含账号预配、HTTP 登录或 TLS |
| GatewayAuth 本地账号生命周期核心 | V01-012 | 已认证管理员复验、账号预配/读取/凭据轮换与恢复/启停、无 secret 幂等审计、最后管理员并发保护，以及强制失败关闭的口令风险端口；仍不包含风险源实现、首位管理员 bootstrap、HTTP/CLI 入口或 TLS |
| GatewayAuth 口令泄露风险适配器 | V01-013 | 固定 HIBP HTTPS origin、SHA-1 五字符 k-anonymity prefix、padding、有界流式响应、严格解析、2 秒超时与有界内存 range cache；不包含 Host 组合、账号入口、bootstrap/recovery 或 live CI 查询 |
| Library / Asset / Scan 只读核心 | V01-004 | 领域与应用层只读用例，不包含生产 host 组合 |
| TaskHealth / outbox 核心 | V01-005 | 核心任务健康与 outbox 语义，不包含完整运维面 |

V01-006 的权限过滤网关、V01-007 的 Transfer/Operation、V01-008 的原生打包均只有组件或沙箱证据。它们分别缺少生产身份与数据库/host 组合、生产耐久文件适配器，以及全部平台生命周期证据，因此不能标记为 `passed`。

## 尚未集成或实现

以下能力当前由政策明确标记为 `blocked_missing_implementation` 或 `deferred_fail_closed`：

| 能力 | owner | 后续任务 | 当前缺口 |
| --- | --- | --- | --- |
| 生产认证 | `gateway-auth-owner` | `V01-AUTH-HOST` | V01-011/V01-012 已提供本地认证、会话和账号生命周期组件，V01-013 已提供尚未组合的生产级口令风险适配器；首位管理员 bootstrap/带外恢复、HTTPS Cookie/Origin 入口、部署 secret 与 host 组合尚未实现 |
| 生产数据库组合 | `database-migration-owner` | `V01-READ-HOST-INTEGRATION` | V01-010 已提供显式启用的只读连接与迁移 readiness，但发布 host 仍允许 `host_only` 模式，尚未由认证后的业务用例把数据库设为必需依赖 |
| host 业务 API | `web-gateway-owner` | `V01-READ-HOST-INTEGRATION` | 发布 host 仍只暴露健康端点，`business_api_ready=false` |
| TLS 与 secret 管理 | `server-packaging-owner` | `V01-TLS-SECRETS` | TLS、证书生命周期、持久 Data Protection key 与部署 secret 尚未集成 |
| 标签、评分与颜色 | `metadata-sidecar-owner` | `V01-METADATA-CORE` | 共享元数据写模型和审计用例尚未实现 |
| 精确查重 | `search-dedup-owner` | `V01-DEDUP-CORE` | 生产强哈希证据和权限过滤查询尚未实现 |
| 软件备份与恢复 | `backup-update-owner` | `V01-BACKUP-RESTORE` | 产品级配置、逻辑状态恢复和升级回滚尚未形成闭环 |
| 生产文件操作 | `operation-trash-owner` | `V01-WRITE-DURABILITY-GATE` | 生产耐久文件系统、operation/session store、审计和批准证据均不存在 |

生产文件写入继续由 `M0-006-G2` 阻断。V01-007 的 task-owned sandbox 结果不能解除该门禁，也不能用于 NAS 或真实用户资产。

V01-010 是数据库 runtime 的组件证据，不是 `production-database-composition` 的关闭证据：未配置数据库环境变量时仍保留 V01-008 的 `host_only` 行为；配置后也始终报告 `business_api_ready=false` 与 `production_file_writes_enabled=false`。在生产认证和只读业务 host 完成组合、数据库成为必需启动依赖，并经单独政策审查前，机器事实源中的该能力必须继续保持阻断。

V01-011 同样只是认证组件证据：迁移 10 和真实 PostgreSQL 测试证明本地凭据、退避、session/CSRF 摘要、版本失效、撤销与重启持久化边界成立，但当前 Host 没有登录端点，也没有生产账号预配、TLS、持久密钥或部署 secret 生命周期。不得直接把认证 service 暴露到现有 HTTP-only Host；在这些边界组合并完成端到端负向验证前，`production-authentication` 必须继续保持阻断。

V01-012 在该边界内补充账号生命周期核心：迁移 11 与真实 PostgreSQL 并发测试证明数据库会再次核验管理员主体和 session version，预配、凭据轮换/恢复、启停、会话失效、无 secret 幂等审计与最后管理员保护成立；Application 层要求所有新口令先通过不可省略的风险检查端口。它没有提供生产风险源、首位管理员 bootstrap、带外恢复或任何 HTTP/CLI 入口，因此仍是 `component-only` 证据，不能解除 `production-authentication` 阻断，也不得连接到当前 HTTP-only Host。

V01-013 只填补上述风险端口的 Infrastructure 实现：完整口令仅在本地以可清理缓冲编码和求 SHA-1，网络请求只包含前 5 个十六进制字符，并由本地 suffix 比对得到 `Allowed` 或 `Compromised`。适配器对非 200、重定向、超时、断连、非法/截断/超限响应和过期 cache 一律返回 `Unavailable`，必测路径全部使用受控 transport 而不访问真实互联网。它尚未被 Host 组合，仍没有 bootstrap/recovery 或外部账号入口，因此 `production-authentication` 继续阻断。

## 外部环境门禁

以下项目需要受批准的隔离环境和真实执行证据；静态脚本、构建产物或 `skipped` 结果都不算通过：

| release target | 开放 gate | owner / 后续任务 | 必需证据 |
| --- | --- | --- | --- |
| `windows-server-release` | `M0-004-G1` | `server-packaging-owner` / `V01-WINDOWS-SERVICE-GATE` | Windows SCM 安装、LocalService 健康、停止、卸载与零残留周期 |
| `docker-release` | `M0-004-G2` | `server-packaging-owner` / `V01-DOCKER-GATE` | 真实 daemon 构建、健康、重启、硬化与 `down --volumes` 残留检查 |
| `linux-server-release` | `M0-006-G3` | `server-packaging-owner` / `V01-LINUX-NAMESPACE-GATE` | 隔离 Linux root/systemd 生命周期和非协作 namespace containment |
| `large-file-release` | `M0-006-G1` | `test-performance-owner` / `V01-LARGE-FILE-GATE` | release-like 的 1、20、100 GiB 真实字节、容量与故障证据 |
| `production-file-writes` | `M0-006-G2` | `operation-trash-owner` / `V01-WRITE-DURABILITY-GATE` | 完整耐久、恢复、冲突、权限、空间、强哈希、审计与垃圾桶证据 |

`v0.1-release` 当前由 `M0-004-G2`、`M0-006-G1` 和 `M0-006-G2` 直接阻断；除此之外，上述未实现能力与 V01-008 的 `partial` 状态也会独立阻断 Alpha release decision。

## 建议后续顺序

1. 在 V01-011/V01-012/V01-013 组件上实现首位管理员 bootstrap/带外恢复，再与 PostgreSQL 运行时和只读业务 host 组合；在 TLS/secret 完成前保持外部登录入口和生产写入关闭。
2. 补齐 TLS、证书、持久密钥与部署 secret 生命周期，再启用 HTTPS Cookie/Origin 入口并做端到端负向验证。
3. 分别实现元数据、精确查重、软件备份/恢复，并由各自 owner 提交独立任务证据。
4. 在独立写入任务中完成生产文件操作与耐久门禁，不复用沙箱结果冒充生产证明。
5. 在批准的容量环境运行大文件与故障门禁。
6. 在批准的隔离 Windows、Linux 和 Docker 环境完成平台周期，并先把 V01-008 从 `partial` 正式裁决为完成。
7. 更新机器政策及相应验证规则，重新运行默认审计和 `--require-ready`；只有所有必需能力为 `passed`、任务输入完成且每个 release target 均允许时，才可称为 release candidate。

V01-009 自身可以在门禁实现、测试和交接都完成后进入 `ready_for_review`，即使 V0.1 Alpha 仍为 `blocked`。这表示判定机制可靠，不表示发布获准。
