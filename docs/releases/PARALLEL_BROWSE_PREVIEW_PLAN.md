# V03-005 — 并行浏览与图片预览交付计划

2026-09-08，用户明确要求拆分到不同窗口并行开发，最后统一验收。本批从70ce45c继续，目标为原生Explorer中的真实资产库入口，以及Web/Android中的真实图片缩略图与基础预览。它是下一批可验收交付，不宣告完整V0.3或V1.0完成。

## 窗口与所有权

| 任务 | 独立窗口 | 独占范围 | 可并行部分与依赖 |
| --- | --- | --- | --- |
| V03-005 | 主协调 | 任务图、共享契约/ADR、根级依赖/CI、集成与部署 | 冻结接口与安全边界，按证据合并并验收 |
| V03-006 | Windows 原生 Explorer | apps/windows-client、tests/windows-client、tests/windows-shell | 从既有加载失败证据继续；不依赖预览实现完成即可诊断 |
| V03-007 | 服务端图片预览 | 批准的PreviewProvider/读取Worker/Host预览适配与测试 | 先提出契约、依赖与隔离方案，冻结后实现；需要核心端口变更由主协调授权 |
| V03-008 | Web 预览接入 | apps/web、tests/web | 先梳理交互与调用方，冻结契约后并行实现 |
| V03-009 | Android 预览接入 | apps/android | 同一冻结契约，手机/平板原生交互与内存边界 |

所有实际线程ID、分支和目录写入 `.codex/task-registry.json`。窗口由Codex App分配独立Git worktree，主协调核对git-common-dir后复用 `scripts/codex-new-task.py` 的任务包/交接生成函数，并为每个窗口绑定独立分支，不再创建第二套工作区。主协调自己的长期写任务使用脚本创建的V03-005 worktree。

仅模块所有者修改该模块。数据库迁移、AssetLink、错误码、权限、根级依赖和生成SDK保持单一写者；工作窗口必须提出具体变更文件/理由，由主协调裁决。需要共享文件时先合并小型契约基线，再让所有消费者更新到同一提交。

## 阶段与验收目标

1. **契约与实现方案冻结。** V03-007提交支持格式、尺寸/字节/并发上限、稳定读取/内容hash缓存、解码隔离、返回状态和依赖评估。主协调形成唯一文件协议；Web/Android不分别猜接口。根级清单与公开端口需要明确owner。
2. **模块并行实现。** Windows集中解决真实Explorer加载及进程外Host；服务端实现有界派生图片；Web/Android实现真实图片请求、视图和状态。解码、凭据、权限、路径与文件逻辑不能进入Shell，不能复制到客户端。
3. **集中自测与审查。** 每个完整实现批次稳定后审查diff，再跑对应的真实格式/构建/协议/平台回归，不逐文件测试，不重复输入未变的成功检查。重型构建最多同时两项；Android模拟器由V03-009独占，避免与大规模后端构建抢资源。
4. **统一集成验收。** 主协调合入同一集成分支，用同一组隔离合成资产和真实Core/PostgreSQL/HTTPS串通Web、Android和可用的Windows入口；再生成包、核对hash与来源。各窗口的单元测试通过不等于整批完成。
5. **受控部署与交接。** 本批服务端/现有NAS Web若需升级，由主协调在可审查包、备份/回滚和检查准备完成后执行；子窗口不得自行部署。保留现有库、账号和快照，不自动启动全库扫描或全库缩略图任务。写标准summary/result/tests，记录实际测试、缺口、来源与清理，再更新状态。

统一验收检查用户实际行为：真实图片缩略图与预览、浏览/搜索/目录导航；权限撤销、换账号和会话到期不保留其他身份画面；取消/超时/断流、损坏和超限文件有明确降级；源变化不会返回错误版本；缓存不可绕过授权；原资产hash/mtime不变。必须核查移动/宽屏、浅深色、键盘/焦点及大字体。Windows必须是真Explorer，不以独立COM探针或另开应用代替。

## 当前门禁与未扩范围

Windows G1..G4仍需真实发现、视图恢复、延迟/取消与稳定性证据；8小时soak不能压缩成Host循环。Provider隔离要求同样不因预览需求而自动通过。V03-007必须区分受信内置解码与外部Provider，明确实际OS/container隔离能力，不能在有Host/DB凭据的进程中解析不可信图片。

本批优先常见静态图片，格式最终由冻结方案与实测决定。PDF/文本等预览、增量索引、标签/查重/文件操作/垃圾桶/产品备份、单向与双向同步、专业资源库/OCR/AI及全平台稳定发行仍按docs16后续依赖推进，不在第一波同时铺开。

客户端不得以原图CSS缩放或假照片声称服务端缩略图已完成。没有实际能力的UI保持准确降级。真实库、凭据、个人素材和生产资产不进入测试夹具或日志；破坏性实验限自有临时目录或sandbox-storage。

## 跟踪与接续

每个窗口在提案、实质阻断和完成时向主协调线程回报task ID、实际路径、commit和证据；主协调据仓库文件复核，而非只相信消息。“等待审批/契约”与“实现中/待集成/已验收”分别记录。后台窗口完成后通过既定主线程回报触发集成接续，不额外创建无限重复轮询任务。
