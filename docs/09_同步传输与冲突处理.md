# 09. 同步、统一传输与冲突处理

## 9.1 统一传输状态

```text
等待中
预检中
传输中
校验中
等待处理
提交中
已完成
部分完成
已暂停
已取消
失败
```

只有目标物理文件提交、可重新读取、完整强哈希一致并建立资产记录后，才算成功。缩略图、OCR和AI不阻塞“安全入库”。

## 9.2 临时接收

官方上传均先进入目标卷临时接收区，不在正式目录暴露半成品。临时内容不搜索、不预览、不整理、不分享。服务重启后可恢复，取消后安全清理。

## 9.3 NAS 内部操作

同卷移动优先快速重命名；跨卷移动为复制→校验→提交→处理源。失败时优先保留源。NAS内部复制必须生成真实副本和新资产 ID。

## 9.4 Windows 与 Android 同步

两端共享三种模式：

### 单向备份

源新增、修改、改名同步到 NAS；NAS变化不反向；源删除默认不删 NAS。

### 双向同步

维护共同基线，双方新增/修改/改名传播；同字段冲突和同路径不同内容人工处理；删除默认进入待确认。

### 移动归档

上传、强校验、正式提交和目标重读成功后，才把源移入 Windows/Android 回收站或系统垃圾桶。

## 9.5 首次同步

首次同步只比较、合并和建基线，不推断历史删除。同路径同哈希配对；同路径不同哈希冲突；同哈希不同路径由用户决定。

同步根不得重叠、互为父子或形成循环。

## 9.6 Android 来源

- MediaStore物理相册/目录；
- SAF用户授权文件夹；
- ACTION_SEND / MULTIPLE一次性投递。

SAF能力不足时自动降级为单向。Android受限目录不承诺直接同步。

Xiaomi HyperOS重点适配：

- 相册安全分享 `content://`；
- 原图同步与安全分享副本区分；
- 动态照片增强 Provider；
- 后台电池限制与通知引导；
- 不依赖私有接口把 NAS 注入系统云相册。

## 9.7 冲突

- 同名不同内容永不静默覆盖；
- 双方同时修改保留两份或人工选择；
- 删除—修改冲突必须人工处理；
- 元数据不同字段尽量合并，同字段冲突提示；
- 强绑定 Sidecar和复合成员作为一个操作单元；
- 批量任务允许部分成功和只重试失败项。

## 9.8 操作锁

浏览不锁。真实写操作使用短期细粒度锁，带任务 ID、节点、心跳和过期。崩溃后先核对物理状态，再恢复或释放，不能盲目重放。

## 9.9 SMB 外部操作

外部操作不属于可控传输任务，而是外部变化批次。系统通过事件、file ID、指纹和哈希重指向索引，保留历史；无法可靠判断时进入待重新定位。
