# ADR-0019 — 首批派生图片预览

状态：Accepted for wire implementation，2026-09-08。用户授权四窗口并行开发和最终统一验收；V03-005协调，V03-007后端，V03-008 Web，V03-009 Android。

## 决定

以 [image-preview-v1](../../contracts/assetlink/image-preview-v1.md) 为唯一新增HTTP契约：既有同源HTTPS会话下，按稳定库/条目ID和固定variant读取服务端生成的PNG。客户端不接收物理路径或任意Provider/尺寸，不通过CSS缩小原图冒充服务端缩略图。512px缩略图适配手机高DPI与现有网格，1600px提供基础预览；派生PNG保留透明并去除源私密元数据。

每次请求重验库权限和源一致性，命中缓存也不省略鉴权；缓存按内容强hash+转换器版本+规格。预览失败/损坏/超限/离线保留现有L0，不改原文件。输入/输出/像素、请求总时限、解码资源与并发必须有界，采用短的同步派生读取和明确busy响应，不建设额外数据库、消息集群或无限任务队列。

权限编排必须留在核心。PreviewProvider不能直接引用GatewayAuth的Application/Infrastructure内部实现；优先由GatewayAuth应用用例复用授权查询，再通过公开Contracts端口调用预览。LibraryStorage已有公开根查询可复用。服务端文件打开和稳定快照在Infrastructure边界，Domain不引用文件系统/HTTP/OS。具体公共端口改动由V03-005裁决，不跨模块写表。

## 尚需落实的实现决策

本ADR先冻结客户端可以并行消费的wire/尺寸/失败语义，不把解码引擎或OS隔离写成已验证事实。V03-007须提交离线解码依赖的精确稳定版本、许可、安全更新/体积/退出策略与实际平台方案；批准前不改根级依赖。

同日根据V03-007提案与官方包/支持表，批准在独立Worker中引入SkiaSharp及SkiaSharp.NativeAssets.Linux.NoDependencies精确4.151.2，中央版本由V03-005写入。许可为顶层MIT，捆绑native notices仍须逐项保留并审计，不能只审核顶层许可；实际win-x64/linux-x64发布增量与漏洞以真实产物审计为准。该版本批准不等于已通过这些检查。退出时替换内部decoder、切换派生版本namespace并清空可重建缓存，无资产/数据库迁移。参考：[SkiaSharp包](https://www.nuget.org/packages/SkiaSharp/4.151.2)、[Linux包](https://www.nuget.org/packages/SkiaSharp.NativeAssets.Linux.NoDependencies/4.151.2)、[维护支持表](https://mono.github.io/SkiaSharp/docs/releases/index.html)。

解码在独立受限Worker内进行，只获得已校验的有界输入快照和固定输出规格，不加载Host/DB凭据或访问原始资产根。清空环境变量、Job Object或单独进程本身不等于文件/网络隔离。Windows与NAS平台的资源、文件/网络边界和进程树恢复必须有实测；不满足的部署保持预览关闭并返回503，不能借“内置”标签绕开原有Provider/原文件安全要求。

批准V03-007在 `services/worker-supervisor/ImagePreview/**` 建立不引用Core/Host/Npgsql的独立decoder；parent marker项目需排除嵌套源码glob。可验证NativeAOT以减少运行时动态加载和虚拟地址预留的不确定性，精确SDK仍为10.0.111。Windows探针仅创建任务拥有的临时AppContainer profile/SID和目录ACL，零网络capability、明确继承句柄列表，挂入CPU/内存/进程数受限Job后才能运行，结束撤销并验证清理。禁止改HKLM/UAC/全局安全配置或增加loopback exemption。

Linux允许在自有沙箱验证预加载后、读取不可信输入前安装TSYNC seccomp-BPF显式allowlist；需禁止文件打开、网络、跨进程访问和exec/fork/io_uring等旁路，限制信号到自身，不允许提升既有资源硬限。RLIMIT/GC与native分配的合成压力必须证明实际总边界，不能将GCHeapHardLimit等同于Skia进程总内存。隔离/资源探针与正常解码必须使用同一初始化路径，失败则关闭能力；这只是验证准入，不是M0-008门禁已关闭的声明。

所需跨界实现由V03-007单写：GatewayAuth/Application新的授权编排、Host的精确预览端点/DI/内部源broker接线、图片endpoint metadata的15秒预算和仅img-src的blob CSP支持。其他JSON/认证/control继续5秒和原CSRF规则，不采用用户可控header或宽泛路径前缀扩大期限。根solution/版本/CI与公开Contracts由V03-005单写；公共端口由双方先提出明确签名再冻结。

原生客户端按既有框架接入，保持JSON接口原有5秒时限，只为有界图片读取设置20秒总体预算。前后台、账号、权限和导航变化取消旧图片并释放内存，URL/bitmap不能跨身份复用。缓存不构成永久授权；本轮没有新增push权限撤销通道。

## 验收

主协调在真实Core/PostgreSQL/HTTPS和同一组可回收合成图片上验证：真实派生尺寸/方向/透明、源码/包对应、损坏和超限拒绝、源变化、缓存与越权/换账号、取消/断流、手机/宽屏与焦点。Windows实际Explorer独立门禁保持原要求。引擎自测和客户端fixture不能替代最终跨端集成，也不能据此宣布完整V0.3完成。
