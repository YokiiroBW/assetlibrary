# ADR-0013：架构与代码质量由自动门禁执行

状态：Accepted / Enforced by M0-009（2026-09-03）

决定：依赖方向、循环依赖、共享契约、数据库迁移、语言预算、代码质量、故障恢复、安全和性能进入三层 CI；每个 Codex 交接必须包含结构化 `architecture_review`。

- `fast-merge`：每次 push、PR 和 worktree review 的仓库、交接、架构、契约摘要及启动门禁，10 分钟内阻断。
- `platform`：Windows/Ubuntu 上的受影响平台测试，单 job 30 分钟；平台 skip 是缺证据，不是通过。
- `scheduled-release`：500k、故障、容量、管理员、Docker、soak 和发布 target，最长 600 分钟，只能在适合且批准的环境运行。

标准库门禁检查 Domain 反向依赖、跨模块内部引用、循环、客户端/Provider 数据库直连、Shell 重型依赖、语言预算、无边界共享目录、生成 SDK 源摘要、M0 blocker 覆盖和 CI 合同。首次出现生产 .NET、TypeScript、Android 或 C++ 清单时，同一提交必须加上该工具链的编译器/分析器原生门禁；文本门禁不是编译器替代品。

残余 M0 blocker 由 `tests/architecture/m0-gates.json` 一对一管理。`deferred_fail_closed` 功能默认关闭；发布 target 只有在全部相关 gate 关闭后才允许。跳过、`continue-on-error` 或只改状态字段不能解除门禁。

后果：M0-009 合并后可按冻结任务图开始 scoped V0.1 implementation，但不授权生产文件写入、Provider、Explorer 或任何平台发布。功能可运行但违反边界、复制核心逻辑或绕过门禁的变更不得合并。详细合同见 `docs/23_M0架构冻结与质量门禁.md` 和 `tests/architecture/ci-tiers.json`。
