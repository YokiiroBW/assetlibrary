# ADR-0014 — 首个只读试用集成与安全部署

状态：Accepted for implementation，2026-09-07。用户已明确要求完成首个可部署只读集成里程碑。协调任务 V01-015；实施任务 V01-016（认证）、V01-017（库/扫描/唯一数据库 owner）、V01-018（Web）。

## 范围与决策

交付 Windows x64 同源 HTTPS Web 只读试用包：安全登录、管理员登记已配置存储源内的物理目录、首次扫描、进度/取消/失败后重试、目录浏览与名称/路径搜索。共用现有 .NET Host、PostgreSQL 与 React/生成 AssetLink SDK，不新增技术栈。先以原生进程运行验证，不冒称 SCM/systemd/Docker 安装已通过。

通过显式 `--read-only-trial <configuration-file>` 启动，与既有默认健康宿主行为兼容。配置只由本机部署者提供，包含唯一 HTTPS public origin、state/证书/持久密钥、各模块最小权限数据库连接文件、已配置 storage source allowlist。根目录和秘密不进入命令行、日志或普通查询响应。静态 Web 只来自构建产物，不将 state 或资产目录作为静态站点根。

真实资产始终只读；登记、授权、索引、会话和任务写入各自数据库，不启用上传、下载原始内容、移动、删除、Provider 或 Explorer。完整 Alpha 和平台 release targets 仍按原门禁判断；本次新增独立的只读试用验收，不拿 scoped trial 代替完整发行证据。

## 认证与信任

- 复用 V01-011..014 的口令、服务端会话、账号与管理员状态机；新增真实受保护部署授权密钥及本机 operator 初始化/恢复/轮换入口。没有匿名 HTTP 初始化/恢复接口。
- Web auth 位于 `/assetlink/v1/auth/login`、`/session`、`/logout`。单个 `__Host-AssetLibrary-Session` Cookie 经持久 Data Protection 保护，Secure/HttpOnly/SameSite=Strict/Path=/。每次请求仍核验数据库，不缓存管理员授权。
- POST 精确核对配置 HTTPS Origin 和 Host；除登录外再核对会话绑定 CSRF，GET session 拒绝异源/跨站访问。CSRF 仅返回同源浏览器内存。无 CORS、无 localStorage credential、无原始连接/异常回显。
- 登录在口令派生前有全局有界速率和并发限制，继续保留数据库账号退避。数据保护 key 必须显式加密并限制目录访问；证书/授权密钥的轮换不能静默改变部署身份。
- 既有账号的离线登录、会话与只读功能不调用 HIBP。首配/恢复/改密仍遵守已有风险端口闭锁策略，当前需要风险源可用；离线首次配置不在本轮实现，后续可信离线风险源不得靠跳过检查替代。
- 受控测试只信任自己的 TLS 证书；不自动修改系统证书信任、UAC、注册表或防火墙。真实浏览器使用受信任证书，安装向导明确提供证书配置步骤，不要求关闭 TLS 验证。
- Windows SChannel 实测不接受 ephemeral TLS 私钥，证书采用 UserKeySet，不加 PersistKeySet/Exportable；由当前用户加密提供程序持有临时容器，Host 退出后确定 Dispose，不导入 X509Store 或信任链。正常退出须核验容器无增减，异常终止另做自有容器生命周期检查。Linux 保持 EphemeralKeySet。DP key仍在私密state中以X509加密。
- 证书续期保留旧DP解密能力：配置可增加至多三个 `decryption_certificates`（`certificate_file/password_file`），都在私密state内。新TLS证书只负责新加密，旧私钥只供历史DP解密，不作为TLS端点，不因旧证书到期而丢失历史key。移除旧PFX前必须证明已无依赖它的持久DP/授权数据，不能直接覆盖删除旧证书。
- 当前TLS证书同时用于DP密钥加密，必须带可用RSA私钥且至少2048位。ECDSA-only证书在加载时以稳定错误拒绝；不能让TLS表面可启动却在首次写DP key时失败。若未来支持ECDSA TLS，须另设DP加密证书并单独验收。
- 真实部署发现HIBP合法range响应超过1,200行且末行可没有CRLF。按[官方range说明](https://haveibeenpwned.com/API/v3#SearchingPwnedPasswordsByRange)的数据增长语义保留严格行内容验证，允许完整末行EOF，并将有界上限设为5,000行/256KiB；2秒网络截止、padding请求、最小800行、重定向/坏数据/重复/溢出闭锁及缓存失效规则不变。合成回归覆盖2,509/5,000行及末行命中，真实外部结果只作兼容性观察，不成为CI依赖。

## 模块与数据库所有权

V01-016 拥有 GatewayAuth 新增 facade/Infrastructure 和 Host/Trial/Authentication，禁止手改共享 SQL。V01-017 是本轮唯一数据库迁移/manifest owner：14 号首先补 GatewayAuth 自有恢复准备函数，之后按 LibraryStorage、AssetIdentity、ScanReconciliation、TaskHealth 的各自 schema owner 追加必要函数/表/授权。旧 1–13 不改；恢复、幂等和升级备份沿既有工具。

库注册的 source ID/比较模式/允许根来自稳定服务端配置，浏览器只提交 source_key/display_name/root_path；禁止通过换 source ID 绕过重叠检查。管理入口统一复用 GatewayAuth 当前管理员策略；所有普通读继续经过原权限投影。各模块只实现自身 SQL 端口，跨模块只用 Contracts/Public，不跨模块写表或引用内部类型。

## 扫描和恢复

复用 InitialReadOnlyScanService 的暂存→完成提交→失败中止，新增有界 PostgreSQL 适配器、持久请求/任务/进度、幂等入队及重启恢复。按已提交 snapshot 事实修复丢失的终态，不能因 journal/响应丢失把已提交索引清除重扫。首次已提交库返回 AlreadyIndexed；本轮不声称实现实时监听或通用重扫。

文件系统探测/发现运行在同一发布二进制的独立只读子进程：`--read-only-worker probe|scan` 在加载 Host/DB/密钥前分派。根只经受限 stdin JSON 传入；stdout 是有界 NDJSON 条目及唯一终帧，stderr 只稳定错误。父进程限帧/背压/截止，取消后杀树并等待退出。EOF、非零退出、缺终帧或数量不符均不算完成；不能用 Task.Run/WaitAsync 留下卡死 NAS 线程。

后台限并发；按任务 lease/fencing/取消和每库独占协调最终提交，恢复核验 AssetIdentity 快照。目录遍历按深度保存枚举器，避免宽目录树积压整个 pending stack。离线状态与上次完成索引分别表达，恢复后可继续读取；失败不误报空库或删除观察事实。

## 验收与兼容

必须完成真实 HTTPS Host + PostgreSQL + 隔离物理目录的浏览器闭环、普通用户直接管理请求拒绝、跨标签会话切换/撤销、Origin/CSRF/限速、初始扫描取消/崩溃/恢复、NAS 断连/恢复、拒权、路径边界及源文件哈希/mtime不变。现有 fast-merge 和相关平台检查继续执行。产出可运行包、启动说明、实测记录与四任务交接。未验证的完整规模、耐久写、预览、平台或 Explorer 能力继续明确关闭。
