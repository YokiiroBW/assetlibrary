# 01. 核心原则与范围边界

## 1.1 物理目录是权威来源

资源库实例必须绑定一个且仅一个真实物理根目录。正式归属、复制、移动、改名、同步和删除都必须在磁盘上真实发生。数据库不使用“苹果相册式逻辑文件夹”代替物理组织。

允许使用逻辑关系的场景：

- 收藏夹；
- 保存视图；
- 时间轴、地图、人物；
- 最近使用、播放进度；
- 标签、评分、颜色；
- 角色关系、资产关系；
- 聚合浏览。

逻辑视图必须显式标识，不得接受含义模糊的拖入、粘贴或同步目标。

## 1.2 文件名不是身份

文件名仅用于展示、搜索与人工参考。稳定身份依靠：

- 稳定资产 ID；
- 稳定文件夹 ID；
- 文件系统事件和 file ID / inode；
- 大小与快速指纹；
- 完整强哈希；
- 明确的导入、复制、移动和 Provider 证据；
- 用户确认。

同名不同内容不能合并；同内容不同路径可能是有意副本。

## 1.3 原文件默认非破坏

默认不改原文件的能力包括：

- 首次扫描；
- 缩略图与预览；
- OCR；
- AI 内容理解；
- 查重分析；
- 在线元数据候选；
- 时间、位置和标注校正；
- 分享预览；
- 图片轻量编辑。

确需写回元数据时必须生成变更计划、预检、临时文件、强校验、原子替换与审计。图片轻量编辑永远保存为新文件，旧图不动。

## 1.4 增强能力不能成为地基

AI、人物识别、在线音乐/电子书元数据、地图、OCR、WebDAV、MCP、浏览器扩展和某个格式 Provider 均属于增强。关闭或失效时，基础索引、真实目录、通用预览、搜索、整理、同步和外部打开仍需正常工作。

## 1.5 系统定位

系统负责：

- 真实资产的发现、索引和跨端浏览；
- 快速预览和轻量标记；
- 可靠传输、同步、整理和垃圾桶；
- 精确与同源查重；
- 元数据、Sidecar、来源与授权；
- 专业软件打开；
- 角色、表情、文本簿等专业资源库视图；
- Web 管理、健康、备份和扩展接入。

系统不负责：

- 专业修图、视频剪辑、CAD/3D 编辑；
- 影视媒体服务器式刮削和字幕管理；
- 多人实时设计协作；
- 项目依赖收集与交付打包；
- 资产原文件备份；
- 私有加密对象仓库；
- 多服务端联邦；
- 全能下载器或网页爬虫。

## 1.6 简单权限、严格内核

用户界面只暴露清晰的系统管理员、普通用户和按资源库权限档位。底层 API、设备、WebDAV、MCP 等仍需最小权限，但不能让日常浏览处处弹确认。只有覆盖、跨库大批量移动、批量删除、永久清理等高风险操作需要显式确认。

## 1.7 代码开发原则

项目采用模块化单体核心、端口适配器与隔离 Worker。业务规则只实现一次，所有客户端与协议入口复用统一应用用例；Domain 不依赖数据库、文件系统、UI或平台 API。每个平台实行语言与框架预算，新增技术栈必须经过 ADR。架构边界、循环依赖、契约兼容、代码质量、安全和性能必须进入 CI。完整规则见 `docs/22_编码与架构开发原则.md`。
