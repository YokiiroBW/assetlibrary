# 03. 资源库与物理目录模型

## 3.1 三层模型

### 资源库分类

决定左侧导航归属：照片、图片、视频、音乐、工程、文档与阅读、角色、通用。分类不绑定路径。

### 专业模板

决定默认专业视图、格式策略、元数据提取、整理台、同步入口和 Provider 建议。例如表情包模板属于图片分类，文本簿属于文档与阅读分类。

### 资源库实例

绑定唯一真实物理根，并保存独立权限和配置。例如：

```text
照片
├─ 我的照片      /Pictures/Me
├─ 父母照片      /Pictures/Parents
└─ 家庭共享照片  /Pictures/Family
```

共同父目录不能再同时注册成重叠资源库。

## 3.2 资源库格式策略

- 严格：不兼容格式禁止写入；
- 引导：提示推荐目标，但允许用户确认；
- 开放：允许混合格式。

专业库默认引导；工程、项目和待整理默认开放。格式只负责路由建议和 Provider 选择，不能单独决定归属。

## 3.3 真实文件夹档案

真实文件夹可拥有稳定 folder ID、封面、简短说明、标签、推荐默认视图、保护和待整理源状态。

- 自动封面和拼贴是缓存；
- 用户指定封面引用真实资产；
- 外部封面必须显式复制到真实目录；
- 简短说明按需写入 `.assetmeta/folder.asset.json`；
- 完整说明使用真实 `README.md`；
- 文件夹标签不自动向子内容继承。

## 3.4 重要目录主页

普通目录默认直接显示内容。角色根、旅行相册、音乐专辑、重要项目等可以选择先显示文件夹主页。主页仅是专业展示，文件仍在真实目录中。

## 3.5 多存储源

一个服务端可管理本机卷、SMB/NFS 挂载和外接盘。每个资源库仍只绑定一个存储源的一个物理根。

存储源离线与文件缺失严格分开。离线库可查看已有缓存和索引，但不执行物理写操作。

## 3.6 重定位、拆分和合并

- 首版提供安全重定位：用户搬好目录后，系统通过相对路径、指纹和哈希重新映射。
- 根目录外部改名可以发现，但必须确认。
- 拆分必须形成不重叠的真实根。
- 合并必须真实移动或复制文件，不做逻辑拼接。
- 移除资源库配置绝不删除资产。
