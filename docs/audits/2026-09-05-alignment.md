# 仓库、旧架构与实现对齐审查

审查起始：2026-09-05；集成验收：2026-09-07。任务：ALIGN-001，配套修复：ALIGN-002、ALIGN-003、ALIGN-004。

## 结论与范围

现有实现总体遵循原架构：真实物理目录为权威、模块化单体、Application/Domain 内统一业务规则、Infrastructure 实现端口、PostgreSQL 单库及模块数据所有权、生成 AssetLink SDK、Explorer/Provider 进程外隔离。没有发现需要更换主语言、第二套框架、额外数据库或拆成微服务的依据。

本次确认的偏差集中在两端遗漏合并、文件系统边界、Web 失败/会话状态、搜索分词、旧 Spike 与新构建基础的兼容，以及启动文档过时。修复不改变需求范围，不启用生产写入、Explorer、Provider 或发布能力。

“组件已有代码”“Host 已组合可用”“平台验证通过”“版本可发布”是不同证据级别。当前仍是 V0.1 受控实现；产品完整度以 `../releases/V0.1_ALPHA_READINESS.md`、`../../eng/v0.1-alpha-readiness.json` 和 `../../tests/architecture/m0-gates.json` 为准。

## 兼容性与安全影响

没有新增主语言、框架、运行时、数据库或重大依赖。没有改公开 AssetLink/操作/权限契约、旧迁移、既有角色及 release gate。新迁移仅替换 AssetIdentity 自有只读函数体，签名、函数身份、owner 和 ACL 经升级前后读回核验；保留 GIN 与 keyset 查询，不以无界全表 substring 扫描替代索引。

启用数据库就绪检查的新版 Host 要求账本达到 13；已有版本 12 的数据库须按既有工具完成已验证备份和前进迁移后才会 ready，Host 不自动升级。Windows 原生 PostgreSQL 工具在过长的测试备份路径下会失败；本轮完整测试使用较短系统临时目录，失败路径保持备份前置闭锁，未修改系统长路径设置或生产数据路径。

所有数据库和文件操作验证使用临时 cluster、角色、系统临时目录或 `.runtime/sandbox-storage/`。未连接生产数据库、未改真实资产、未注册 Shell、未运行服务安装/卸载；NAS 写入限最后的 Git 主线同步。

扫描的检查仍有普通路径 API 的微观 TOCTOU 限制，尚未证明 no-follow 句柄或 NAS 内核阻塞隔离；检查成本约为 O((条目数 + 目录数) × 祖先深度)。它修复明确可重现的联接逃逸，不将有限测试扩大成完整不可信并发文件系统保证。生产写入和相应隔离门禁继续阻断。

## 后续优化顺序

1. **先组合已完成组件形成受控只读闭环。** 沿现有 GatewayAuth/Host 端口实现真实带外授权与可轮换 secret、TLS/持久 key、认证会话和业务 Host，再完成权限撤销/重启/过期/错误 Origin 的端到端负向验收。避免继续堆没有可运行入口的小组件。
2. **在生产启用前补文件系统与规模证据。** 用真实 50 万资产/深目录/离线 NAS 测量新增路径复验、keyset/GIN、取消和后台调度成本；明确 no-follow/句柄身份及执行隔离方案后再开放能力。不得用缓存祖先检查换取可绕过的边界。
3. **按 owner 实现当前缺失的 V0.1 能力。** 元数据、精确查重、软件备份/恢复和耐久文件写入分别收敛；统一复用权限、计划、审计及物理事实。不要扩为第二数据库、Redis、搜索或消息集群。
4. **最后推进客户端和 Explorer。** Windows 独立客户端先稳定视图/生命周期，Explorer 保持最小桥接；按自定义 COM 发现、视图/卸载、故障时限与 20 次恢复/8 小时 soak 逐门禁提交证据。Host-cycle helper 只证明其有限循环，不是 Explorer soak。

代码组织已有足够清晰的模块边界。较长的迁移/发行校验和集成测试文件可在其下一次实际修改时按独立职责拆分；不为减少行数重复实现规则、重写冻结迁移、拆成无实际复用的接口层或全面格式化旧文件。历史交接保留，当前入口仅链接权威状态，避免继续复制进度事实。
