# 02. 已确认需求基线

## 2.1 资源库与导航

- 左侧层级固定为：资产库根 → 资源库分类 → 具体资源库实例 → 真实物理子目录。
- 资源库结构分为：分类 → 专业模板 → 实例。
- 固定分类：照片、图片、视频、音乐、工程、文档与阅读、角色、通用。
- 类型分组和“全部某类库”是聚合视图，不是物理目录。
- 同一专业模板可以创建多个实例，例如“我的照片”“父母照片”“家庭共享照片”。
- 每个实例拥有独立物理根、权限、同步、格式策略、缓存、AI、OCR、查重、WebDAV和公网策略。
- 不允许资源库父子路径重叠。

## 2.2 用户与资源库权限

权限模型只保留：

- 系统管理员；
- 普通用户；
- 具体资源库实例权限。

资源库权限档位：

```text
不可见
只读
可读写 / 上传
可整理（改名、移动、垃圾桶、查重处理）
资源库管理员
```

库内子目录默认继承，不做逐文件或复杂子目录 ACL。需要不同隐私边界时拆成新的真实资源库。

## 2.3 统一资产元数据

- 标签最多三级，拥有稳定 ID、别名、合并和适用范围。
- 星级为共享 1–5 星。
- 颜色为“无颜色 + 固定颜色”，名称可自定义。
- 自定义字段只提供有限类型，不支持脚本和公式。
- 收藏夹可创建多个，默认个人，可显式共享。
- 保存视图仅保存筛选条件与范围，删除不影响文件。
- 标签/评分/颜色对资产组批量应用时必须明确范围。

## 2.4 扫描、索引与外部变化

- 首次扫描只读，分阶段先可用后补全。
- 实时监听 + 定期轻量核对 + 手动完整扫描。
- SMB、File Station、SSH、专业软件导致的移动/改名要尽量重指向原资产 ID。
- 源仍存在时按复制创建新资产 ID；源消失且唯一强哈希匹配时可重指向。
- 大批量目录移动优先批量更新路径前缀。
- 整个存储源离线不能判成全部文件缺失。
- 单文件缺失保留 30 天宽限期，再由用户确认清理索引。
- 系统和临时文件默认忽略；符号链接不递归跟随；未知格式至少 L0。

## 2.5 待整理、整理与自动化

- 专用 Inbox 和任意 NAS 真实目录均可登记为待整理源。
- 待归类表示目标库未知；待整理表示目标库已知但尚未正式归档。
- 整理默认按具体资源库或入站批次隔离。
- 格式用于推荐和校验，但不能拆散专辑、模型包、项目目录和复合资产。
- 全系统共用一个规则引擎。
- 执行级别：仅提示、加入整理计划、自动执行。
- 自动执行只允许在入站/待整理目录中的低风险确定性任务。
- 正式库内移动、跨库移动、工程文件改名和 AI/OCR 推断命名必须人工确认。

## 2.6 搜索、OCR、查重和 AI

基础搜索包含：文件名、真实路径、格式、标签、评分、颜色、自定义字段、格式元数据、全文与本地 OCR。

排序优先级：

```text
文件名完全命中
路径与名称部分命中
结构化元数据与标签
原生正文
OCR
AI语义
```

AI 是可选增强：

- 可立即参与语义搜索和结果排序；
- 未确认前不能成为正式标签、标题或描述；
- 不得认定人物身份、角色归属、授权或物理目录；
- 不得直接移动、改名或删除。

查重层次：

- 完整强哈希精确重复；
- 像素一致或转码一致；
- 图片同源、裁剪、压缩、分辨率不同；
- AI 只辅助难例分析。

跨个人库重复默认只报告，可能是有意副本。

## 2.7 传输与同步

所有官方传输共用统一会话：

```text
预检 → 临时接收 → 分块/断点续传 → 强校验 → 冲突/重复 → 正式物理提交 → 资产记录
```

支持：

- Windows 文件夹同步；
- Android 相册和指定文件夹同步；
- 浏览器扩展；
- Web 上传；
- WebDAV；
- NAS 内部复制和移动；
- Developer API / MCP 的受控投递。

同步模式：

```text
单向备份：源 → NAS；源删除默认不删 NAS
双向同步：维护共同基线；删除默认待确认
移动归档：NAS完整提交与重读校验后，源进入本地回收站
```

首次双向同步只合并并建立基线，绝不推断历史删除。

## 2.8 垃圾桶与保护

- 用户侧只有一个统一垃圾桶。
- 普通删除、查重清理和整理撤回统一进入垃圾桶，通过原因区分。
- 支持保留周期、恢复、批次筛选和永久清理权限。
- 文件和真实文件夹可设置简单“已保护”，阻止误移动、改名、覆盖、垃圾桶和写回。
- 自动化、同步、查重、API 和 MCP 不得绕过保护。

## 2.9 预览、编辑与导出

- 所有文件至少 L0；支持格式可获得缩略图、预览、轻量操作和外部打开。
- 图片轻编辑只包含裁剪、旋转/翻转、文字、线条、箭头、框、高亮和马赛克。
- 编辑结果必须保存为新文件和新资产 ID，原图不变。
- 正式导出必须选择真实目标目录；临时分享兼容副本只存在缓存。
- 音视频只做基础播放和临时代理，不做通用正式转码器。
- DWG/DXF、MAX/C4D/SKP 首期以基础索引、伴随预览和专业软件打开为主。

## 2.10 专业资源库

- 照片：时间轴、地图、人物、EXIF、GPX、实况、连拍。
- 图片：瀑布流、色彩、透明、HDR、来源、同源分析。
- 表情包：角色/系列物理目录，情绪和语境标签，快速分享，未来输入法接口。
- 音乐：专辑墙、艺术家、歌曲、歌词和底部播放栏；官方元数据增强。
- 视频：基础播放、故事板、时间码标注和外部播放器。
- 文档与阅读：PDF、Markdown、Office只读、电子书、漫画、网络小说元数据。
- 文本簿：选中文字、网页正文、MHTML、截图和来源记录。
- 工程/3D：混合物理目录、通用3D预览、伴随预览与专业软件打开。
- 角色：身份证式主页、模块化人设、相册、日记、关系、全部资产和联动。

## 2.11 客户端与服务端

官方客户端：

- Web；
- Windows 独立客户端；
- Windows Explorer 集成；
- Android / 平板同一响应式应用；
- Chromium 浏览器扩展。

服务端正式发行：

- Docker / Docker Compose；
- Windows x64 原生 EXE / Windows Service；
- Linux x86-64 原生可执行程序 / systemd。

macOS 首期不考虑。

## 2.12 接入、网络与外部系统

- 官方客户端使用独立 AssetLink 协议。
- 客户端支持主链接、备用链接和用户设定优先级。
- 通过真实 HTTPS/API 健康探测切换，不能只看 Ping。
- 局域网/VPN 提供完整能力，公网 HTTPS 提供受控浏览、同步、上传和下载。
- WebDAV 默认关闭，启用后默认只读。
- Developer API 默认关闭，开发者模式启用并使用访问令牌。
- MCP 预留查询、状态、投递和两阶段物理操作工具。
- AstrBot、Hermes、Codex 可通过官方插件或 MCP 连接。

## 2.13 性能、健康、备份与更新

- 首版 50 万资产正式验收，设计预留 100 万。
- 单文件至少 100GB，流式处理。
- 1–10 用户、1–5 台活跃 Windows 客户端。
- Explorer、滚动、搜索和首屏不得被后台任务拖慢。
- 软件备份只包含 PostgreSQL、配置和不可重建逻辑数据，不包含资产。
- 更新采用受控半自动，更新前备份，支持 Provider 独立回滚和安全模式。
- 健康中心区分系统、资源库和单资产故障。

## 2.14 编码与架构工程基线

- 架构采用领域模块化单体 + 端口适配器 + 隔离 Worker，不默认拆成大量微服务。
- 权限、路径、哈希、传输、同步、文件操作、垃圾桶、保护和审计等业务逻辑只能在核心实现一次。
- Domain 不得依赖 UI、数据库、文件系统、网络或平台 SDK；跨模块不得直接访问内部类或写其他模块的数据表。
- Web、Windows、Android、Explorer、WebDAV、Developer API 与 MCP 只做适配，不复制领域规则。
- 每个平台只允许一个主语言/主框架；新增语言、框架、数据库、搜索或消息基础设施必须有批准 ADR。
- 禁止 God Service、万能 Utils、循环依赖、共享可变全局状态、魔法字符串和未版本化契约。
- CI 必须包含格式化、静态分析、架构边界、契约、迁移、单元、集成、安全、故障恢复与性能回归门禁。
- 每个 Codex 子任务必须提交结构化 `architecture_review`；能运行但破坏边界的实现不得合并。
