# 19. 技术待决策与风险清单

## 19.1 M0 必须验证

1. Windows 11 Shell namespace extension + custom `IShellView` 能否稳定承载进程外专业视图。
2. AssetLink最终采用何种控制编码、事件通道和浏览器兼容方案。
3. 服务端核心框架和Windows/Linux/Docker三发行的单代码库可行性。
4. PostgreSQL任务队列、outbox、lease与大规模搜索是否足够，无需额外Redis/搜索集群。
5. 跨卷移动、崩溃恢复和操作锁的状态机。
6. Provider进程隔离、超时、内存/CPU限制和跨平台分发。
7. Windows/Android双向同步的基线与大规模目录改名性能。
8. 50万资产下缩略图、全文、OCR和瀑布流的真实P95。

## 19.2 高风险模块

- Explorer深度集成；
- 双向同步和删除传播；
- Android SAF多Provider写能力；
- 大文件断点传输与线路切换；
- SMB事件丢失和目录级重指向；
- RAW/PSD/Office跨平台Provider；
- 人物与AI隐私；
- WebDAV老旧客户端兼容；
- 在线网络小说Provider长期维护。

## 19.3 M0-009 已冻结与仍待实现选择

已冻结：

- 服务端 C# 14 / .NET 10 LTS / ASP.NET Core 10；
- PostgreSQL 16.x 为唯一数据库、基础搜索、任务租约与 outbox 底座；
- Web TypeScript 6.0.x / React 19.2.x / Node.js 24 LTS；
- Windows 客户端 C# / WinUI 3 / Windows App SDK 2.x stable；
- Windows Shell C++17 / Windows SDK 10.0.26100 / COM/C++/WinRT；
- Android Kotlin 2.3.x / Compose stable BOM / AGP 9.x；
- AssetLink v1 基线使用 HTTPS JSON、NDJSON 事件流与流式字节，不在 V0.1 引入 Protobuf 双编码。

仍需在真实实现中选择，但不得扩大技术预算：

- PostgreSQL 的具体数据访问库、生产权限查询和相对路径索引；
- Web 状态管理/组件库及本地缓存加密与失效；
- Provider RPC 的生成绑定与 cancel ack 实现；
- 地图、音乐、书籍首批数据源。

这些实现选择必须由真实用例、可运行测试和必要 ADR 冻结。不得把“尚未选库”解释为可以引入第二数据库、第二服务端、第二前端或桌面框架。

## 19.4 工程质量收敛任务

M0-009 必须在各技术 Spike 完成后确认：

- 最终语言/框架版本与语言预算；
- 模块内部目录和依赖规则；
- C#、TypeScript、Kotlin、C++ 的架构测试工具；
- 契约生成与消费者兼容测试；
- 数据库迁移与模块数据所有权；
- lint、复杂度、重复代码、依赖漏洞与许可证门禁；
- 性能回归和故障注入进入 CI 的执行分层。

M0-009 已完成上述规则与 CI 合同收敛，允许按冻结任务图开始受控 V0.1 实现。开放的 Explorer、发行、文件持久性、大文件和 Provider 隔离风险仍按 `tests/architecture/m0-gates.json` fail-closed；不能仅凭开发进度启用或发布。
