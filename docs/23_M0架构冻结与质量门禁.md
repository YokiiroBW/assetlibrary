# 23. M0 架构冻结与质量门禁

状态：Frozen for scoped V0.1 implementation（2026-09-03）

维护说明（2026-09-05）：M0 审计表保留当时证据与裁决；当前已激活的构建/测试以 `tests/architecture/ci-tiers.json` 为准，组件进度见 `docs/releases/V0.1_ALPHA_READINESS.md`。后续原生门禁激活不会自动关闭本章 residual gates。

本章是 M0-009 的权威收敛记录。它只授权按本章任务图开展 V0.1 的隔离、只读或沙箱内实现；不等于允许启用生产文件写入、不可信 Provider、Explorer 扩展，也不等于任何平台可发布。机器可读的残余门禁位于 `tests/architecture/m0-gates.json`，CI 分层位于 `tests/architecture/ci-tiers.json`。

## 23.1 结论

- M0-001 至 M0-008 的提交、交接、测试计数、平台跳过、风险和 blockers 已逐项核对。
- 当前没有未关闭的 `blocking_v0_1_start`，因此允许创建并行受控的 V0.1 实现任务。
- M0-002、M0-004、M0-006、M0-008 仍保持 `partial`；它们的 12 个 blocker 全部一一映射到后续门禁，不能因 M0-009 合并而改成完成。
- `v0.1-release`、生产文件写入、Windows/Linux Provider、Windows/Linux 服务端发布和 Explorer V0.5 仍有开放阻断项；跳过测试不能解除阻断。M0-004-G2 后续由 V01-021 的真实 NAS Docker 生命周期与回收证据单独关闭，完整 Alpha 仍受其他门禁约束。
- 架构基线从“检查文件存在”升级为标准库实现的阻断检查，并为每类规则提供可通过与应失败的测试夹具。
- PostgreSQL 16 足以作为当前唯一数据库、任务租约、outbox 和基础搜索底座；在真实指标持续超预算且有批准 ADR 前，不引入 Redis、第二数据库、独立搜索或消息集群。

## 23.2 证据真实性规则

以下四个状态不得混用：

| 状态 | 含义 | 当前授权 |
|---|---|---|
| 允许开始编码 | 架构、所有权和沙箱边界已冻结，可实现受控任务 | V0.1 scoped implementation：允许 |
| 允许启用功能 | 对应运行时安全门禁已关闭，可让用户实际使用 | 文件写入、Provider、Explorer：不允许 |
| 允许发布平台 | 该平台安装、运行、故障、卸载和发布门禁全部通过 | 当前所有正式发布目标：不允许 |
| 完成最终验收 | 版本路线中的性能、权限、安全、soak 和恢复证据全部完成 | 不允许 |

所有 `skipped` 只表示当前运行器不具备证据条件，不计为通过。Spike 代码、候选协议和模拟器只证明其交接明确列出的性质，不自动升级为生产实现。

## 23.5 技术栈冻结

“证据级”表示已有本仓库 Spike；“预算级”表示 M0-009 为首个生产清单选择单一技术族，但首个实现任务仍必须建立并运行该平台工具链。版本补丁必须由仓库清单和锁文件固定，不能依赖运行器浮动版本。

| 范围 | 冻结预算 | 证据级别与激活条件 |
|---|---|---|
| 服务端核心、Worker、Windows/Linux/Docker Host | C# 14、.NET 10 LTS、ASP.NET Core 10 | M0-004 已以 .NET 10.0.11 验证进程宿主；首个生产 solution 必须 pin `10.0.x` SDK 并加入 restore/build/test/vulnerability/license 门禁 |
| 数据库 | PostgreSQL 16.x、原生 SQL 迁移 | M0-005 以 16.15 验证；生产只接受受支持的 16.x 补丁，升级 major 需 ADR 与迁移/恢复证据 |
| Web | Node.js 24 LTS 构建、TypeScript 6.0.x、React 19.2.x | 预算级；首个 `package.json` 必须同提交提供锁文件、Node pin、lint/type/test/audit/license 命令 |
| Chromium 扩展 | TypeScript 6.0.x、Manifest V3 | 预算级；复用生成 TypeScript AssetLink SDK，不建第二套协议客户端 |
| Windows 独立客户端/AssetHost | C# 14、.NET 10、WinUI 3 / Windows App SDK 2.x stable | 预算级；首个实现固定精确 stable patch，禁止并存第二桌面 UI 框架 |
| Windows Shell | C++17、Windows SDK 10.0.26100、COM/C++/WinRT | M0-002 Spike 证据；生产源根在 Explorer 门禁关闭前保持未激活，只允许最小 IPC/视图桥接 |
| Android/平板 | Kotlin 2.3.x、Jetpack Compose stable BOM、AGP 9.x | 预算级；首个 Gradle 构建固定 wrapper、BOM/插件补丁和 dependency verification，不混入 Java 业务实现 |
| WebDAV、MCP、内置 Provider 适配 | C# 14 / .NET 10 | 预算级；只能依赖 Application/公开契约，禁止直连 PostgreSQL；Provider 必须运行于隔离进程 |
| 工具、生成、仓库门禁 | Python 3.12+ 标准库优先 | M0 已验证；不进入产品运行时，不成为第二服务端 |

版本族参考各厂商在 2026-09-03 的受支持稳定线；这只用于选择维护线，不构成项目运行证据。升级策略是：安全补丁在同一已冻结 major/minor 内经 CI 合并；minor/major 或框架替换必须有 ADR、回退方案和消费者兼容证据。

版本选择的官方维护入口：[.NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy)、[Node.js releases](https://nodejs.org/en/about/previous-releases)、[React versions](https://react.dev/versions)、[TypeScript 6.0 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-6-0/)、[Windows App SDK downloads](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/downloads)、[Compose BOM](https://developer.android.com/develop/ui/compose/bom)、[Android Gradle Plugin releases](https://developer.android.com/build/releases/about-agp) 和 [PostgreSQL versioning policy](https://www.postgresql.org/support/versioning/)。每次 bootstrap/升级仍须重新核对支持状态并将精确值写入仓库。

重大依赖评估必须记录许可证、安全更新渠道、跨平台支持、二进制/镜像体积、维护 owner、替代与移除路径。M0-009 本身没有新增运行时依赖。

## 23.6 模块与数据所有权

生产服务采用 `services/core-server/Modules/<Module>/{Domain,Application,Infrastructure,Contracts}`。模块所有权如下：

| 模块 | 唯一拥有的状态/政策 |
|---|---|
| GatewayAuth | 身份上下文、资源库授权编排和公开入口政策 |
| LibraryStorage | 物理库根、存储可用性和库级权限状态 |
| AssetIdentity | 资产/目录稳定身份和观测到的物理事实 |
| MetadataSidecar | 已确认元数据、标签、评分、Sidecar 与来源 |
| ScanReconciliation | 只读发现、外部变化观察和身份重指向 |
| TransferSync | 传输会话、续传字节、同步基线和冲突 |
| OperationTrash | 物理操作计划、锁、校验、保护与垃圾桶 |
| SearchDedup | 搜索投影、精确重复证据和批准的只读模型 |
| PreviewProvider | 预览请求、派生产物和 Provider 调度政策 |
| TaskHealth | durable task、通知、健康、诊断和 outbox 发布状态 |
| BackupUpdate | 软件备份、恢复、更新和回滚编排；永不拥有资产原文件 |

依赖固定为 `Adapters/UI/Gateways -> Application -> Domain`，Infrastructure 仅实现核心定义的端口。跨模块只允许公开 Command/Query、端口、版本化契约、领域事件或经批准的只读投影；禁止内部实体引用、跨模块写表和循环依赖。

数据库单一所有权：

- `migration` ledger 与迁移执行器由 `database-migration-owner` 独占；所有生产迁移序号、checksum 和发布顺序由该 owner 分配。
- 每个业务模块拥有自己的 PostgreSQL schema、表、写模型和迁移片段；共享实例不产生共享写权限。
- M0-005 的 `library.asset` 等对象是 Spike 证据，不自动冻结为生产表归属。V0.1 首个模型任务必须按上表拆出唯一 owner，或在写 SQL 前提交最小 ADR/Contract Change Proposal。
- `TaskHealth` 拥有 task/outbox 投递状态；业务模块在自身事务内写其批准的 outbox 接口，不直接更新发布租约。
- 查询跨模块状态只能使用批准的只读投影；任何跨 schema 写入均为架构门禁失败。

共享契约单一所有权：

- `contracts/assetlink/**`：`assetlink-contract-owner`；消费者只能通过版本化契约和生成 SDK 使用。
- `contracts/providers/**`：`provider-contract-owner`；Supervisor 与 Provider 都不能单方面改协议。
- `packages/sdk/assetlink/{dotnet,typescript,kotlin}`：`sdk-generation-owner`；生成代码禁止手改，源契约摘要不一致即 CI 失败。
- 统一错误码、操作计划和权限契约在首次创建前必须由主协调线程指定唯一 owner；未指定前禁止多任务并行创建同名契约。

## 23.7 可执行架构门禁

`python scripts/validate_architecture_baseline.py` 当前阻断：

1. Domain/Application 的反向或平台依赖；
2. 跨模块 Infrastructure/内部层引用及模块循环；
3. 客户端、Gateway、MCP、Provider 直连 PostgreSQL；
4. Shell 的网络、数据库、媒体解码和重型依赖标记；
5. 各产品源根的语言预算、构建清单和锁/验证文件；
6. 有内容的无边界 `common/shared/utils/helpers` 目录；
7. AssetLink 生成消费者的源摘要一致性；
8. M0 partial blocker 的完整一对一覆盖、fail-closed 默认值和可执行 release target；
9. 三层 CI 合同、真实工作流、超时和跳过政策。

当前产品目录仅有说明文件时会报告 inactive/not-applicable，不把空目录标为“已验证”。规则测试使用临时仓库构造正反夹具；每一类禁止行为至少有一次应失败断言。文本扫描是第一道防线，不能替代激活后的 Roslyn/编译器、TypeScript、Gradle 或链接器依赖图；首次生产清单必须在同一变更中激活对应原生门禁。

禁止并行修改区域：根级锁/版本、`contracts/**`、`database/migrations/**`、生成 SDK、统一错误码、权限契约、操作计划契约、`.codex` 协调器状态和发布版本。需要跨 owner 的变更先提交 Contract Change Proposal，由主协调线程排序，不允许工作线程自行扩权。

Explorer 生产实现不属于 V0.1；Windows/Android 客户端和不可信 Provider 分别遵循 V0.3/V0.5 门禁，不能为赶 V0.1 抢跑。

## 23.10 解除、回退与审查

- 门禁关闭必须同时更新源任务证据、`m0-gates.json` 状态、解除条件证据和对应 CI；只改 JSON 状态无效。
- 任何技术族替换、第二数据库/搜索/消息集群、跨模块写模型或 Shell/Provider 信任边界变化必须先有 ADR。
- 架构误报可通过缩小规则到明确边界修复；禁止全局排除目录或 `continue-on-error`。临时豁免必须有 owner、到期日期、目标范围和恢复测试。
- 若后续证据推翻某个冻结选择，立即将受影响目标改回 fail-closed，并在新 ADR 中记录回退/迁移路径。
